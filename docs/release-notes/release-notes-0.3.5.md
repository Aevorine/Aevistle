# Aevistle 0.3.5

撰写页报的两个毛病是**同一个 bug**，而且它随时可能让整个界面塌掉。整个界面一直是用
**Times New Roman** 排的 —— 那个叫 `--font-sans`（无衬线）的变量装的是衬线字体。

这一版是 32 项，全部做完，其中一项没做全 —— 在最后一节。

---

## 撰写页：一个原因，两个症状

**报告的是两件事**：正文输入框上下高度很小，以及"正文"两个字分成了两行。**实际是一处根因。**

正文框的尺寸完全挂在 `.field:has(.textarea--body)` 上 —— 全项目 **30 条**这样的规则，
六个文件。`:has()` 要 Chromium 105 以上，而这个 build 的 `minSdkVersion` 是 **24**（安卓 7）。
一台 System WebView 没跟上的机器，这 30 条**同时失效**。

在浏览器里把这 30 条规则删掉再量：

| | 30 条在 | 30 条失效 |
|---|---|---|
| 正文框 | 475px（占 72.7%） | **128px（19.6%）** |
| "正文"标签 | 隐藏（sr-only） | **显示出来** |

**两个症状一次全出来。** 现在改成显式类名 `.field--body`，从 React 里挂上去，
任何 WebView 都不会失效。同一轮里 `dvh`（Chromium 108）也换掉了 —— 同一个坑。

### 顶上那条提醒条没有高度上限

`MAX_ROWS` 限了**条数**，没有任何东西限**一条能有多高**。360×800 实测：

| 设定 | 提醒条 | 正文框 |
|---|---|---|
| 标准字号 | 79px | 475px（72.7%） |
| 大号字 | 131px | 331px（58.7%） |
| 大号字 + 系统再放大 1.3 倍 | **341px** | **230px（42.8%）** |

红线写的是 85%。**三种情况一个都没达标。**

现在每条限两行，真的超了才长出「展开」—— 用 `scrollHeight > clientHeight` 在节点上量，
不是按字数猜，因为同一句话在 360px 是一行、在 320px 加系统放大就是四行。

第一版写反了：**没加钳制就去量溢出**，永远量不到，按钮从不出现。修好后：

| 最坏设定 | 之前 | 之后 |
|---|---|---|
| 提醒条 | 341px | **127px**（点开 727px，再点收回） |
| 正文框 | 230px（42.8%） | **385px（62.4%）** |

### 打字时头部收成一行

账号 / 收件人 / 主题两行 88px，答的都是一封信只答一次的问题。手指落进正文那一刻收成
一行 44px，三个答案还都在。正文框 **475px → 545px（80.7%）**。

截图才看出来的问题：三段全被截成「选... › 还没有收... 关于下周三的会...」，
**三个省略号没一句能读**。改成账号不缩、收件人保底 5 个字、主题先截。

### 收件人粘贴

以前只按 ASCII 逗号分号空格拆。从中文文档里复制的用的是 `，``；``、`，
从邮件客户端复制的是 `张三 <a@x.com>` —— 前者整段变成一个假收件人，后者多出一个叫"张三"的。
9 个用例全过，包括带引号且引号里有逗号的 `"Zhang, San" <a@x.com>`。

## 整个界面一直是衬线体

用画布量字宽，探针字符串在界面里渲染 **168px**：Times New Roman 正好 168，
Arial 182.4，无衬线 196.7。按钮、标签栏、设置行、收件箱、**验证码数字**，全是 Times + 宋体。

`theme.css` 的注释自己承认了："The name is a historical misnomer now"。
而 `--font-mono`（等宽）直接 `= var(--font-sans)`，所以验证码是**比例宽度的衬线数字**。

现在分成三个：

- `--font-sans` 真无衬线（Segoe UI Variable / PingFang SC / Noto Sans SC…）—— 界面
- `--font-prose` 保留 Aevistle Text（Times + 宋体）—— **读信正文和撰写正文**
- `--font-code` 真等宽（ui-monospace / Cascadia Mono / Consolas）—— 验证码、字节数、时间戳

实测：标签栏 Segoe UI Variable Text，撰写正文宽度 **97.3px = 正好 Times New Roman**
（无衬线是 102.2）。

**换字体当场暴露了一条死规则。** `01-base.css` 里那条"撰写正文用宋体"写的是
`.textarea--body`，权重 (0,1,0)；而 `04-forms.css:318` 的 `.textarea { font-family: inherit }`
同权重、文件更靠后，**一直赢**。以前 `--font-sans` 本来就是宋体，输赢画出来一模一样，
所以没人发现。改 `textarea.textarea--body` (0,1,1)。

要换回去是一个变量的事。

## 两个 reducer 崩溃

新的开信测速探针跑出来的，都是真的：

1. `mergeRemoved` 用 `?? []` 只挡 null 和 undefined，**形状不对的值照样进 spread 然后抛**——
   而且是在 reducer 里抛：dispatch 被放弃，界面停在半路。探针里的表现是**收件箱从 12 行变 0 行**，
   看起来像"我的邮件不见了"。`removed` 是**存盘字段**，旧版本写的、崩溃时写一半的、手改过的，
   都会喂给它。
2. `runUpdateCheck` catch 了抛异常，**没管返回 null** —— 这个函数存在的全部意义就是
   "更新检查不能弄坏别的东西"，它只做了一半。

## 闸门

**新增两个，修好三个，其中一个是我自己写错又抓回来的。**

- `check:ui-consistency` —— 专门查风格漂移的脚本，**六轮以来根本没接进检查链**，
  要手工开着调试端口才能跑。现在自驱动、进链、会失败。10 项属性 10 个界面全部在阶梯上，
  **页面标题 24px×5** —— 五个界面终于一个字号
- `check:contrast` —— 以前只读 theme.css 且**跳过所有 `color-mix()`** 还算通过。
  现在算 **2175 对**，139 个已知失败列成基线，包括从没被量过的主按钮白字配青底 **3.74:1**
- `check:css` 的重复属性规则 —— 只认列 0 的单类选择器，且 `depth === 0`
  让**所有 @media 里的规则全部免检**（30 个块）
- `check:layout` —— 它量之前先把提醒条 `display:none` 掉，所以报 85.9% 合格而真实是 72.7%。
  现在**两个数都量**：85.9%（模拟）和 72.7%（真实屏幕），后者有自己的 55% 红线
- `audit.mjs` 的 INBOX-08 —— 按**变量名** `dataUri` 匹配。重构成共用的 `safeImageDataUri()`
  之后它报了 HIGH 级 HTML 注入，**对着一段确实在校验的代码**。改成检查行为。
  改完第一版**删掉校验它照样通过**（截取的函数体延伸到了后面也调用同一函数的地方）——
  删掉校验再跑才发现。现在：原样通过 → 删校验报 HIGH → 恢复再通过

至此，这个项目「看着在把关、其实没量对东西」的案例累计 **11 个**。

## 没做全的

**开信测速闸门（第 15 项）建起来了，但没进检查链。**

它能跑，能启动真应用、种 12 封信、量到真实数字（冷开 **154.7ms**，iframe 在 86.4ms 挂载），
而且抓出了上面那两个 reducer 崩溃 —— 这些都是真的。

但它**目前是红的**：假 bridge 在"开信 → 关信 → 再开"之后，列表变成 0 行
（标签栏还显示 12），我没能定位到是哪一步。**把一个红的闸门塞进发版链，只会教会所有人忽略它**，
所以它作为 `npm run check:open-mail` 单独存在，没进 `npm run check`。

要不要接进去、以及那个 0 行是不是真机也会出现，等下一轮。
