# Aevistle 0.3.26

0.3.25 说"你不在的时候来的邮件，现在会告诉你了"。**它说错了 —— 在笔记本上。**

这一版从同一句反馈开始：「电脑、手机、平板关了之后还是收不到实时提醒」。
0.3.25 的五处修复都还在、都还对，但它们全部挂在一个前提上：
**每 15 分钟有人把应用拉起来一次。** 而在笔记本上，那个"人"从来没动过手。

---

## 一、计划任务建好了，但 Windows 给它配了一套让它永远不跑的设置

这是这一版的主角，也是这个项目至今为止最典型的一个"全绿但没用"。

「退出之后也继续收信」这个开关做的事是注册一个计划任务，每 15 分钟静默启动一次应用。
0.3.25 用的是 `schtasks /Create /SC MINUTE ...` 这种命令行开关的写法。
问题在于：**这种写法只能描述"什么时候跑"，描述不了"在什么条件下才准跑"。**
描述不了的部分，Windows 全部按它自己的默认值填。

在这台机器上把任务导出来看（`Export-ScheduledTask`，不是推测，是原样读回来的）：

| 被默默填上的设置 | 默认值 | 实际后果 |
| --- | --- | --- |
| `DisallowStartIfOnBatteries` | **true** | **笔记本一拔电源，这个任务永远不会启动。整个功能，关掉。** |
| `StopIfGoingOnBatteries` | **true** | 比不启动更糟：跑着跑着拔了电源，**任务计划程序会把 Aevistle 直接杀掉** |
| `ExecutionTimeLimit` | **PT72H** | 被拉起来的应用是要常驻的，而任务计划程序把常驻算成"跑了三天"，**到点杀掉** |
| `StartWhenAvailable` | **false** | 睡眠中错过的那次触发，醒来后不补 |

这台机器是笔记本（机箱类型 10，电池 HB4692Z9ECW-22T）。
也就是说：**只要没插电，0.3.25 的所有修复一次都不会被执行到。**

而应用内部完全看不见这件事。设置页问的是"任务在不在"，任务**确确实实在**，
所以开关一直显示"已开启"，任务计划程序里一直显示正常。
**注册成功和真的会跑，是两件事，而这个应用之前只会问前一件。**

改法：

- **改用 XML 注册**（`schtasks /Create /XML`）。这是 `schtasks` 唯一能设置这四项的形式，
  四项全部按相反的值写死。
- **写完之后把注册好的任务读回来核对。** 退出码 0 只证明"XML 语法没错"，
  不证明"设置生效了"。企业策略、被管控的机器都可能覆写。核对不过就在设置页说出来。
- **设置页多了一句实话**：任务在、但设置不对时，不再只说"已开启"，
  而是说"这台机器一拔电源它就不会运行，把开关关掉再打开会重建一次"。
- **老版本装机的坏任务会自动修好。** 之前的写法是"只有开关的值变了才重写任务"，
  而一个开了几周没动过的开关永远不会变 —— 那些 0.3.24 / 0.3.25 建下来的坏任务
  会一直留着。现在每次启动重写一次，代价是两条 `schtasks` 调用。

### 修的时候差点又踩一遍同一个坑

第一版改完之后，顺手往任务里加了一个**登录触发器**（开机进桌面就先查一次，
不用干等满一个 15 分钟）—— 听起来纯赚，代码写完门禁全绿，编译通过。

然后拿真机试注册，Windows 回了三个字：**拒绝访问。**

逐个元素删掉再试，答案很干脆：

| 文档内容 | 用普通账户注册 |
| --- | --- |
| 完整文档（带登录触发器） | **拒绝访问** |
| 去掉 `<LogonTrigger>` | 注册成功 |
| 去掉 `<AllowHardTerminate>`（仍带登录触发器） | **拒绝访问** |
| 带显式 `<UserId>`（仍带登录触发器） | **拒绝访问** |

**登录触发器需要管理员权限。** 而注册失败的后果是：代码退回到旧的命令行写法 ——
也就是**这一整版要修的那个 bug 原封不动回来了**，而且开关照样显示"已开启"。

一个"顺手加的小优化"，会让整个修复静默失效。所以登录触发器不加了，
门禁里加了一条：**文档里不准出现任何需要提权的元素。**

`AllowHardTerminate` 关掉（不允许被硬杀）保留 —— 单独测过，它不需要提权。

最后一步是拿**真正要打进安装包的那个文件**（`dist-electron/main.cjs`，不是源码）
把 XML 抠出来，用一个临时任务名注册进 Windows，**再从任务计划程序里读回来核对**，
然后删掉那个临时任务：

```
schtasks accepted the document.
  ok    DisallowStartIfOnBatteries = false  (asked for false)
  ok    StopIfGoingOnBatteries     = false  (asked for false)
  ok    StartWhenAvailable         = true   (asked for true)
  ok    ExecutionTimeLimit         = PT0S   (asked for PT0S)
  ok    Command   = D:\APPS\Aevistle\Aevistle.exe
  ok    Arguments = --hidden
```

这一步还顺带抓出第三个错：读回来的内容一开始全是"缺失"。
原因是 `schtasks /Query /XML` 输出的是 **UTF-8**（虽然它打印的文档头写着 UTF-16），
而 `schtasks /Query` 不带 `/XML` 输出的才是 UTF-16。按错的编码解，
得到的是一串乱码，里面一个标签名都匹配不上 —— **于是一个完全健康的任务会被报成四项全坏。**
两种编码现在都处理，门禁也钉住了这一条。

## 二、手机上「从最近任务里划掉」＝后台收信直接结束

安卓这边的后台收信靠一个前台服务，每 90 秒同步一次。
在原生 Android 上，前台服务能扛住"划掉应用"这个动作。
**但这个应用大多数时候不在原生 Android 上。**

华为、荣耀、小米、三星都自带后台管理，划掉应用时会把整个进程杀掉，前台服务一起带走；
`START_STICKY`（"系统请把我拉回来"）是**系统**的承诺，这些管理程序同样可以不认。
症状非常具体：**手机自带邮箱一直在收信，这个应用从划掉那一刻起彻底安静，
直到你下次打开它。而且哪里都不会有一句提示。**

现在，划掉应用时会做两件事，故意做两件是因为它们在不同的机型上失效：

1. **用闹钟在 5 秒后把服务再拉起来。** 这是唯一能把 90 秒的循环救回来的办法，
   也是可能被拒绝的那个 —— 安卓 12 以后从后台启动前台服务受限，
   这里依赖的是"精确闹钟"那条豁免，所以没给过「闹钟和提醒」权限的机器会落到第 2 条。
2. **把 15 分钟的定期任务重新排一次。** 这条通常不吃紧（它本来就能扛住划掉），
   但它不要钱，而且第 1 条被拒绝时，就是它在继续送信。

这段代码里任何一步都不允许抛异常：它跑在系统正在拆掉任务的时候，
这里抛出去，用户看到的是**"我一关它就崩了"**。

## 三、依赖里有一个高危漏洞，而发版门禁正因为它而是红的

顺着"独立安全审计"这条查依赖，`npm run audit:deps` 是红的，三条高危：

```
FAIL  high  deepmerge-ts
FAIL  high  html-to-text
FAIL  high  mailparser  (直接依赖)
```

三条其实是同一条：**mailparser → html-to-text → deepmerge-ts**。
根在最里面那个 —— [GHSA-ggr8-5vv4-36mx](https://github.com/advisories/GHSA-ggr8-5vv4-36mx)，
`deepmerge-ts < 8.0.0` 合并**自引用的对象**时会把调用栈撑爆。
而 `mailparser` 正是解析**别人发来的邮件**用的那个库，这条链子直接挨着不可信输入。

npm 给的"修复建议"是把 `mailparser` **降级**到 3.9.8（倒退六个补丁版本，
其中包含邮件解析本身的修复）。没采纳。改成直接把 `deepmerge-ts` 顶到 `^8.0.1` —— 也就是
真正打了补丁的那个版本。

但 `html-to-text` 声明的依赖范围是 `^7.1.5`，强行顶到 8 是越过它的声明，
所以**不能靠"能装上就算好了"**。做法是先固定一份基准：拿一封故意写得很难看的 HTML 邮件
（标题实体、多余空格、列表、表格、引用块、`<pre>`、中文验证码、带 alt 的图片）
过一遍 `mailparser`，把 `text` 和 `textAsHtml` 原样存下来；换完依赖再跑一遍，**逐字节比对**。

```
IDENTICAL — html-to-text output unchanged under deepmerge-ts 8
```

一个字符都没变。这件事必须验，因为 `html-to-text` 产出的正文摘要，
就是新邮件通知第二行显示的那段字 —— 也就是这一版在修的那个功能。

锁文件的改动范围也核对过：**只有 deepmerge-ts 一个包**（7.1.5 → 8.0.1），
外加把锁文件里一直停在 `0.1.37` 的版本号补成当前版本。

## 四、门禁

`check:background-mail` 从 9 项扩到 34 项。新增的部分只盯一件事：
**"任务已注册"不等于"任务会跑"。**

| 新增检查 | 钉死什么 |
| --- | --- |
| 必须用 XML 注册 | 命令行开关的写法根本表达不了设置，退回去就红 |
| 四项电池 / 超时设置的值 | 逐项写死，改回默认值就红 |
| 写和读回必须来自同一张表 | 只写不校验、或只校验不写，都会红 |
| XML 必须以 UTF-16 写盘 | 写成 UTF-8 时 `schtasks` 只报"XML 格式错误"，指向完全无关的地方 |
| `<Command>` 里不准带引号 | 带了引号那就是一个不存在的路径，**注册成功、运行时才失败** |
| 老任务必须能被自动重写 | 只在开关变化时重写，就等于永远不修已经装在机器上的那些 |
| 安卓：划掉应用必须安排重启 | 而且必须是闹钟，不能只指望 `START_STICKY` |
| 安卓：关闭路径不准抛异常 | 否则用户看到的是关应用时崩溃 |

每一项都验证过：**把它要测的东西改回错的值，它会红**（实测把
`StopIfGoingOnBatteries` 改回 `true`，门禁立刻红，其余 33 项照常通过）。

## 还没做的事，写在这里而不是留白

**安卓端没有真正的 IMAP 长连接。** 那边是 90 秒轮询一次（服务活着时）或 15 分钟
（只剩定期任务时）。桌面端有长连接，所以桌面端应用开着的时候是真正的即时。
把安卓也做成长连接是一个大改动，不在这一版里 —— 现在说的"实时"，
在安卓上准确的说法是**最快 90 秒**。
