# Aevistle 0.3.7

这一版是 5 件点名的事。其中**两件报上来像是两个毛病，查下去是同一个原因**：
一行动画收尾的写法，让手机和平板上所有弹出的页面都盖不满屏幕。

另有一件是"以前是并排的，现在变成竖着排三行了"——不是谁把它改竖了，是它**排不下**。

---

## 弹出的页面左右留白，盖不满屏幕

**报告的是**：设置界面点开一项，弹出来的页面左右是空白的，没有完全覆盖。

先说测到的数字。360×800 的手机，点开"外观"：

| | 应该是 | 实际是 |
| --- | --- | --- |
| 遮罩层 | 360 × 800 | **328 × 1326** |
| 弹出页面 | 从 x=0 起，360 宽 | **从 x=16 起，328 宽** |

左右各留了 16px 的页面底色，高度还比屏幕高出去 526px。

### 原因是一个"什么都没做"的动画

手机上每次切换页面，内容会有一个 120ms 的滑入。它是这么写的：

```css
:root[data-shell='mobile'] .view__inner {
  animation: viewarrive 120ms ease-out both;   /* ← 就是这个 both */
}
```

`both` 的意思是"动画放完之后，**最后一帧继续留着**"。而最后一帧是：

```css
to { opacity: 1; transform: translate3d(0, 0, 0); }
```

`translate3d(0, 0, 0)` —— 移动 0 像素。它不挪动任何东西，屏幕上看不出任何区别。
但在 CSS 里，**一个元素只要带着 transform（哪怕是 0），它就会变成自己内部所有
`position: fixed` 元素的"参照物"**。

弹出页面的遮罩层正是 `position: fixed; inset: 0` —— 它本来参照整个屏幕，现在改成
参照那个带 padding 的内容栏了。于是"铺满"铺的是内容栏，不是屏幕。

改动是一个词：`both` → `backwards`。`backwards` 只在动画**开始之前**生效，而这里没有
延迟，所以那段时间长度是 0 —— **滑入的观感一帧都没变**，变的只是 120ms 之后
transform 会正常消失。改完再量：遮罩层和弹出页面都是 360×800，从 x=0 开始。

这个坑不只影响设置。**手机和平板上，凡是从页面里弹出来的东西都受影响**，收件箱的
阅读页也一样——报告里只提了设置，是因为设置里弹得最多。

### 加了一道门禁，因为这种 bug 看不出来

症状里没有任何东西指向病因：弹窗的样式规则是对的，`width: 100%` 也确实生效了，
只是算出来的数不对；而闯祸的那一行在一个讲页面切换动画、通篇没提过弹窗的文件里。

所以新增 `npm run check:fixed-cb`：扫描所有样式文件，只要有哪条规则给"可能包着弹窗
的容器"挂上一个**带 transform 且收尾会保留**的动画，就让构建失败。淡出类的动画
（最后一帧 `opacity: 0`）不算——那种元素已经消失了，包不住任何东西。

**这道门禁自己是能失效的，所以它自测**：脚本里存着 0.3.6 那段出问题的原文，每次运行
都拿它跑一遍，如果连已知的老 bug 都测不出来了，就直接报"门禁已经失灵"。

（验证方式：把 `backwards` 改回 `both`，门禁退出码 1 并指出是哪一行；改回来，退出码 0。）

## 主页三个数字，从三行变回一排

**报告的是**：今天要发 0 封 / 今天已发 0 封 / 今天失败 0 次，要像以前一样并排，
用卡片隔开，背景恢复原来的颜色。

之前这三个数字是三颗"药丸"，和右上角的搜索按钮挤在同一行，靠 `flex-wrap` 换行。
在 360px 的手机上量：三颗药丸约 460px，可用的行宽只有 280px —— **一行只塞得下一个**，
于是折成三行，那条蓝色横幅为了显示三个数字从 48px 长到了 168px。

这不是调参数能解决的。**一个会换行的行，本身就是"不保证排成什么样"**，而这里需要的
是无论多宽的屏幕、哪种语言，都排成同一个样子。

所以改回三等分的网格：`repeat(3, 1fr)`。一格就是三分之一，俄语也是三分之一。
背景是原来那层 13% 的白色叠加，中间用 1px 竖线隔开——三张卡片从同一块底板上切出来，
而不是三个方块摆在一起，这样整条永远是 56px 高。

每格上面是数字、下面是说明（`0 封` / `今天要发`）。**量词跟着数字走，所以拆成两行
之后一个字也没少。**一格约 109px，而"今天要发 0 封"写成一行需要 130px —— 硬要塞进
一行，只能把数字缩小，而数字正是隔着半米也要看清的那个东西。

问候语（早上好/晚上好）回到了顶行，和搜索按钮一排。

## 收件箱：图标一行，主题一行

**报告的是**：邮件点开后，标注优先级、删除、在邮件中查找、关闭这五个图标要在最上面
一行，主题显示在第二行。

这条规则**代码里早就写了**，写在 0.3.5，但在部分安卓机上从来没生效过。原因和 0.3.5
修过的那个是同一类：

```css
.modal:has(> .modal__body--reader) .modal__header { ... }
```

`:has()` 是 Chromium 105 才有的选择器。本应用的 `minSdkVersion` 是 24，遇到不支持
`:has()` 的 WebView，**整条规则会被判为无效，直接当不存在**——不报错，不警告，
样式表看上去完全正常。于是恰恰在最需要这条规则的机器上，主题和五个图标继续挤在一行。

改成 `data-variant="reader"`：由 `Modal` 组件自己在面板上盖一个属性，样式表直接选它。
属性选择器是 Selectors 2 时代的东西，**这个应用能跑起来的引擎全都支持**。

顺带把生效范围从"窗口宽度 < 840px"改成"手机/平板外壳"。1024px 的安卓平板超出了那个
宽度界限，拿到的是桌面版的单行标题栏——**同一个报告的另一半（平板）之前根本没被覆盖到**。

五个图标全部保留在第一行，没有折进"更多"菜单里——它们是被点名要求显示的。360px 手机
上实测：五个图标加关闭按钮共 296px，行宽 328px，放得下；再给这一行加上"禁止换行"，
免得某种语言或者系统字体放大之后悄悄挤掉一个到第三行。

改完实测（360×800）：五个图标都在 y=16 那一行，主题在 y=80 独占整行 328px 宽。

## 撰写界面：删掉"已经没有下一次了"那句

**报告的是**：删除撰写界面里"1 条提醒开着，但已经没有下一次了"。

这句话不是故障提示。一个已经发过的单次提醒、一条结束日期已过的规则，都是**做完了
该做的事**的任务。在一个人打开来是为了**写信**的界面上，用警告的语气报一件不用处理
的事，代价是信纸变短——而且这一行永远不会自己消失，每完成一个提醒它就加一。

只在撰写界面不显示。定时任务界面仍然照常统计——**那里才是放着这些任务的列表**，
在一堆不会再触发的任务上面写"一切正常"是不对的。

## 收件箱默认显示图片

**报告的是**：收件箱要求默认显示图片内容。

改了，默认值从"不加载"改成"加载"。这是一个取舍，把代价写在这里：

远程图片是**发件人指定的服务器上的一张图**。自动加载它，等于在你打开邮件的那一刻，
从你的网络地址向对方发一次请求——**这会告诉发件人三件事**：这个邮箱地址是活的、
邮件是什么时候被读的、读它的 IP 是多少。营销邮件塞一张 1×1 的透明图，就是为了这个。

**但比听起来的要小**，因为下面这些没有变：

- 邮件正文的框**永远不联网**。图片是主进程单独取的，正文框的 CSP 只允许 `data:`。
- 主进程那一侧防内网探测的护栏（`electron/remoteImage.ts`）两种设置下都在。
- **随邮件一起下载的内嵌图（`cid:`）本来就在本机**，零请求、零泄露，从来不受这个
  设置影响。

设置里那个开关还在，三个选项（不加载 / 总是加载 / 只对白名单发件人）一个没少。
**你改过一次之后，就以你改的为准**，以后这个默认值再变也覆盖不了你的选择。
