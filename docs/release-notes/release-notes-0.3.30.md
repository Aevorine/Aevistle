# Aevistle 0.3.30

一句话：**手机和平板上，你点了哪个格子，那一屏的左上角就再把那几个字念一遍给你听。
这一版把那句话拿掉了，并且加了一道闸门，保证它不会再长回来。**

---

## 一、你问的那件事：为什么每个界面左上角都在写功能名

先说结论：**这是一个真的 bug，不是设计**。而且它藏得很深——藏在一个"看源码看不出来"的地方。

### 它是怎么发生的

这个应用早就有一条规矩，写在 `PageHead` 这个组件里，原话是：

> 你按下去的那个标签已经亮着、上面已经写着那几个字了，
> 在内容顶上再印一遍等于什么都没说，还白占一条横带。

所以**每一个界面**都老老实实地把自己的标题藏起来了。九个界面，一个不漏。
我逐个查过源码，全部正确。

问题出在**手机上根本没有九个标签**。手机底下只放得下五个：撰写、验证码、主页、收件箱、设置。
剩下的定时任务、工作日历、联系人、模板、发送记录、可靠性中心、配对——
在手机上是从**主页的格子**点进去的。

而主页的格子，是用一个**全屏弹层**把那些界面装进去的。
那个弹层自己会画一行标题，标题内容是——**你刚按的那个格子上写的字**。

于是就成了这样：界面自己把标题藏好了，装它的那个盒子又把同一句话写了回去。
两边各自都"对"，合起来就是你看到的那样。

### 现在是什么样

| | 改之前 | 改之后 |
| --- | --- | --- |
| 点「定时任务」格子 | 左上角 25px 处：**定时任务** | 什么都没有，直接是内容 |
| 点「工作日历」 | 左上角：**工作日历** | 直接是日历 |
| 点「联系人」「模板」「发送记录」「可靠性中心」「配对」「更多」 | 同上，各念各的名字 | 全部直接进内容 |

一共七个界面，加上「更多」这一屏，八处。**每一处都省下一整条横带**，
在 390×844 的手机上是 55px——差不多是列表里多半行内容。

关掉的只是**画出来的那几个字**。读屏软件（视障用户用的）仍然会念出你打开了哪一屏，
因为那个名字还在无障碍树里，只是不再画在屏幕上。这跟应用里其它八个界面的做法完全一样，
所以现在全应用**只有一种**处理方式，没有例外。

### 为什么它不会再长回来

新加了一道闸门：`npm run check:screen-titles`。

它会真的开一个 390×844 的窗口，把五个底部标签 + 八个主页格子**逐个点一遍**，
然后检查每一屏顶上 60px 里，有没有一段可见文字**正好等于**你刚按的那个控件上的字。
有就不通过，并且指出是哪一屏、在几个像素的位置、由哪个元素画的。

这道闸门我当场验过它真的会拦：把修复撤掉重跑，它一次点名七个界面并以退出码 1 失败；
把修复放回去再跑，全部通过。它已经接进 `npm run check`，跟其它七十多道闸门一起跑。

> 顺带说明：这道闸门只管**位置**，不管**词**。
> 「定时任务」这四个字出现在定时任务界面的空状态文案里是完全正常的，
> 它只拦"标题该出现的那个位置上，出现了你刚按过的那个词"。

## 二、顺手修掉的一个：应用打不开时，那句话有一半是英文

这次排查时撞上的，之前没人报过——因为它只在**应用启动失败**的时候才看得见。

那一屏原本长这样：

```
Aevistle 无法启动                                    ← 中文
The desktop bridge did not load, so Aevistle ...     ← 英文，写死的
你的数据没有被改动。如果一直这样，重装一遍……          ← 中文
```

三句话，中间那句是英文。而且不只中文版——西班牙语、法语、俄语、阿拉伯语版本
看到的中间那句**也是英文**，因为它是在抛错误的地方直接用英文写死的，
从来没有进过翻译文件。

**这是整个应用里最需要看懂的一屏**，偏偏是唯一一屏读不全的。

现在三种启动失败各有一句自己的话，六种语言都有。技术细节（真正的报错原文）
单独放在下面一个灰色的框里，**故意不翻译**——那一行是拿去贴给别人看的，
翻译过的报错帮不上任何人。

---

## 三、这一版没动什么

- 收发信、定时、通知规则、同步、加密——一行没动。
- 桌面版的界面一处没动（桌面上侧栏有全部九个标签，本来就没这个问题）。
- 你的设置、账号、定时任务、已收邮件，全部原样。

---

## 升级方式

- **电脑**：设置 → 关于 → 检查更新；或者直接下新的安装包盖上去。
- **安卓**：下 `Aevistle-0.3.30.apk` 覆盖安装，数据不动。
  如果系统提示签名不一致，说明你之前装的是别处来的包——先卸载再装。

校验：`SHA256SUMS.txt` 连同它的 GPG 签名 `.asc` 一起发布，
公钥指纹 `57753E473F94B09DB3AA9A6AB865B328D5535D9B`。
