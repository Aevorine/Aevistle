# Aevistle 0.3.9

一件事：**手机上打开邮件，发件人地址不再一个字母一行竖着断开了。**

0.3.7 和 0.3.8 都记了这个问题没修，这一版修掉，并且加了一道会真的失败的门禁。

---

## 它到底为什么会竖着断

发件人那一行是一个横向排列的行，里面五样东西：

| | 宽度 | 能不能被压缩 |
| --- | --- | --- |
| 头像 | 32px | **不能**（固定尺寸） |
| 发件人（名字 + 地址） | 36px | 能——所以少的全从这里扣 |
| 时间戳 | 141px | **不能**（写死了不许压缩） |
| 账号标签 | 24px | 已经从 60px 被挤扁了 |
| 展开箭头 | 48px | **不能**（点击区下限） |

360px 的手机上，去掉左右边距还剩 328px。不能压缩的三样占 221px，四个间距占 48px，
**剩给发件人和账号标签的只有 59px**。发件人拿到 36px。

地址那一行有一条规则叫"实在放不下就从任意位置断开"。这条规则本身是对的——**地址跑出
对话框外面比断行更糟**——但在 36px 宽的格子里，"任意位置"就变成了每三个字母断一次：

```
zhan
gsan
@exa
mple.
com
```

五行。整条发件人栏 126px 高。

**平板上更惨**：600–840px 那个双栏布局里，右边栏约 394px，同一行还多三个图标按钮，
发件人分到 **0px**，地址断成 **20 行**，整条栏 **399px 高**——一封邮件的发件人是谁，
根本读不出来。

---

## 为什么不能靠"挤一挤"解决

这一行没有多余的像素可以匀。时间戳那 141px 是你要核对的事实，展开箭头那 48px 是手指
点击区的下限，地址至少需要约 140px 才存在。**这一行需要第二行。**

而且第二行是白赚的：原来那 126px 是"碎掉的地址"占的，改成两行干净的排布之后是 **91px**，
反而更矮了。

```
[头像]  张三                                    [v]
        zhangsan@example.com
        2026年8月11日 22:30   [Primary]
```

---

## 但原来那条"必须一行"的规则是有道理的，没有丢

这条栏在你往下读邮件的时候会吸顶并且缩成一条窄条。原来强制它单行，是因为**一条会随
发件人名字长短改变高度的吸顶栏，会在你眼皮底下把正文顶来顶去**。

所以新规则只在"没有缩起来"的时候生效。缩起来的状态本来就会隐藏地址和账号标签——地址
一藏，时间戳就放得下了，那条栏还是一行、还是原来的高度。**滚动时的行为一个像素都没变。**

桌面版完全没动：桌面阅读窗 1240px 宽，发件人从来没被挤过。

宽度是按"另外三样东西加上间距占了多少"算出来的，不是写死的 224px——以后头像尺寸、
点击区下限或者间距改了，这一行会跟着走，不需要谁记得回来改。

---

## 平板上还剩三行，如实说明

双栏那个 394px 的窄栏里，同一行还有三个图标按钮，所以排下来是：第一行头像+发件人、
第二行那三个按钮+箭头、第三行时间+账号标签，**130px**。

没有再为这一档单独写一套宽度计算。原因是量出来的数字：**399px → 130px 是修复本身；
130px → 108px 要换一个"必须知道那排按钮有几个"的算式，而这种算式在有人往那排加一个
按钮的第一天就会算错。**

---

## 新门禁：`check:reader-meta`

这个 bug 静态检查抓不到。**牵涉到的每一条 CSS 单独看都是对的**，错的是它们在某个宽度
下加起来的结果——而"弹性基准 + 间距 + 点击区下限"的和，不是拿正则扫样式表能算出来的，
必须让真的浏览器排一遍版。

所以新增一个探针，用和 `check:layout` 同一套无头 Chrome，在 360x800 和 760x1024 两个
宽度上真实测量，断言四件事：

1. 地址最多占 2 行（长地址占两行是允许的，那是"宁可断行也不截断"的既定选择）
2. 发件人栏至少 120px 宽——**把病因和病症分开断言**，这样以后再犯时报的是"栏位被饿死了"
   而不只是"地址断了"
3. 静止状态整条栏不超过高度上限
4. **缩起来的状态必须还是一行**——这是原规则的承诺，修复不许把它花掉

另外还测了一封"只有地址没有显示名"的邮件：那种情况下名字那一行就是地址本身，必须
省略号截断而不是换行。

**验证过它会真的失败**：把 `flex-wrap` 改回 `nowrap` 重跑——

```
FAIL  phone 360x800: 地址断成 5 行（上限 2）。发件人栏被饿死了——只有 38px。
FAIL  two-pane 760x1024: 地址断成 20 行（上限 2）。发件人栏被饿死了——只有 0px。
FAIL  two-pane 760x1024: 静止高度 399px，超过 170px 上限
5 passed, 5 failed
```

改回来：`10 passed, 0 failed`。

**探针里所有等待都是轮询，不是固定 sleep。** 第一版用了固定等待，跑第四遍就随机失败了
一次（列表是虚拟滚动的，行还没渲染出来就去点了）。**会随机失败的门禁比没有门禁更糟**：
第一次抖动就教会所有人"重跑一遍就好了"，然后第一次真正的回归也会被重跑到没人再看。
改成轮询后连跑三遍全绿。
