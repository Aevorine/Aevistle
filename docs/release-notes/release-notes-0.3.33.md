# Aevistle 0.3.33

一句话：**收件箱整个页面画不出来的真正原因找到了，是日期。**

0.3.32 说修好了"正文空白"。它修的是真问题，但**不是你碰到的那个**——所以你装上之后
"还是原样"，这个反馈是对的。这一版修的是那个真正的原因。

---

## 一、先说结论：不是邮件取不回来，是**收件箱这一整屏根本没渲染**

### 你屏幕上其实发生了什么

打开收件箱，React 在画消息列表的中途**抛了一个异常**。异常被外面那层
`ErrorBoundary` 接住了，于是整屏被换成了那块灰色的失败面板：

```
此界面无法显示
Invalid option : option
账号、定时任务和邮件都不受影响，数据还在，其它页面照常能用。
                                                     [重试]
```

按「重试」它会重新画一遍，然后**在同一个地方再抛一次**，于是又变回这块面板。
电脑、手机、平板三端一模一样——因为这是同一份界面代码，安卓装的也是这份。

**邮件一直都在。** 这台机器上的缓存里躺着 187 封信的完整正文（其中一封 123KB、
带 16 张图），五个邮箱今天还都同步成功了，一条错误都没有。取信这一环从头到尾没坏过。
坏的是"把它们画到屏幕上"这一步。

### 那句 `Invalid option : option` 是什么

消息列表每隔一段会插一条日期分隔条：**今天 / 昨天 / 星期三 / 8月3日**。
第三种——"星期几"——用的是浏览器内置的日期格式化器，代码这样叫它：

```
formatDateTime(时间, { weekday: 'long' })     // 我要"星期三"
```

而 `formatDateTime` 自己会先垫两个默认值进去：

```
{ dateStyle: 'medium', timeStyle: 'short', weekday: 'long' }
```

问题就在这里。浏览器的日期格式化器把**"整体样式"**（`dateStyle`/`timeStyle`）
和**"单个部件"**（`weekday`/`month`/`hour`…）看成两种互斥的写法：
你要么说"给我一个中等长度的日期"，要么说"给我星期几"，**不许两个一起说**。

两个一起说的后果**不是**忽略其中一个、也不是退回默认，而是**直接抛异常**：

```
TypeError: Invalid option : option
```

六种语言全都抛，换哪个浏览器引擎都抛。这是标准规定的行为，不是 bug。

### 为什么它会炸掉**整屏**

因为它是在 React **画界面的过程中**抛的，不是在某个按钮的回调里。
渲染中途抛异常 = 这棵组件树画不完 = `ErrorBoundary` 接管 = 整屏换成失败面板。

一条日期分隔条，带走了整个收件箱。

### 什么时候会碰上

`dayLabel` 的规则：

| 这封信有多旧 | 分隔条写什么 | 要不要格式化日期 | 会不会炸 |
| --- | --- | --- | --- |
| 今天 | 「今天」 | 不要（是个词） | 不会 |
| 1 天 | 「昨天」 | 不要（是个词） | 不会 |
| **2–6 天** | **「星期三」** | **要，而且是"部件"写法** | **炸** |
| 7 天以上 | 「8月3日」 | 要，但是"样式"写法 | 不会 |

也就是说：**只要你的收件箱里有任意一封 2 到 6 天前的邮件，收件箱就打不开。**

任何一个真实在用的邮箱，两天之内必然满足这个条件。所以对你来说它不是偶发，是**一直坏着**。

## 二、为什么这个仓库里的 78 道闸门一道都没拦住

这是这次最需要写下来的一条。

**每一个测试用例里的邮件，日期都是几分钟一封。**

- `open-mail-probe.mjs`：12 封信，每封间隔 **10 分钟** → 全部落在两小时内 → **全是「今天」**
- `inbox-reader-probe.mjs`：5 封信，每封间隔 **1 小时** → 全部落在 5 小时内 → **全是「今天」**

「今天」这一档是**唯一一档不需要格式化日期**的。于是所有闸门年复一年地只走那一条分支，
另外三条从来没被走到过——其中一条一走就炸。

0.3.32 新加的那道 `check:inbox-reader`（"打开一封邮件，正文不许是空的"）也一样：
它的 5 封信全是今天的，所以列表能画出来，它就一路测到了正文，然后报告一切正常。

**闸门本身没坏，是喂给它的数据不真实。** 这个仓库之前已经记过十二次同类问题，
这是第十三次。

### 这一版怎么补的

**三层，每一层都验证过"把修复撤掉它会红"：**

1. **`npm run check:date-labels`（新增）**
   - 把「今天 / 昨天 / 星期几 / 具体日期」四种分隔条，在 **6 种语言 × 14 个时间点 ×
     跨午夜的 4 个钟点**下全部格式化一遍，一共 56 个标签 × 6 语言。
   - 而且它**会检查自己有没有真的走到「星期几」那一档**——如果哪天规则改了、那一档
     再也走不到，它会直接报"这个 gate 什么都没测到"而不是安静地全绿。
   - 另外它会**把 `src/` 里所有 `formatDateTime(…, { … })` 的写法扫出来**（这次扫到
     21 处），每一处都在 6 种语言下真跑一遍。**以后新写的调用自动进保护范围，
     不需要谁记得来改这个文件。**
   - 撤掉修复后：**19 条红**。

2. **两个真机闸门的测试数据改成跨天**
   `open-mail-probe` 和 `inbox-reader-probe` 里的邮件间隔从 10 分钟 / 1 小时改成
   **36 小时**，于是每次运行屏幕上都同时有「今天」「昨天」「星期几」「具体日期」四种。
   - 撤掉修复后，`check:inbox-reader` 报的是：
     ```
     FAIL  desktop: the mailbox drew 0 rows for 5 seeded messages.
     FAIL  tablet:  the mailbox drew 0 rows for 5 seeded messages.
     FAIL  phone:   the mailbox drew 0 rows for 5 seeded messages.
     ```
     **三端全红，而且报的正是你看到的那个症状。**

3. **`check:date-labels` 已接进 `npm run check`**，跟另外 77 道一起跑，发版前必过。

## 三、修法：不是改那一行，是让这种写法从此不可能出错

只改 `InboxView` 里那一行当然也能好，但下一个人写
`formatDateTime(x, { month: 'numeric' })` 的时候会原样再踩一次——这次是收件箱，
下次可能是日程表。

所以改的是 `formatDateTime` 自己：

> **调用方一旦点名了任何一个"部件"（星期/年/月/日/时/分/秒/时区…），
> 就只给它点名的那些，两个默认样式不再垫进去。**
> 就算调用方自己同时写了样式和部件，样式也会被丢掉，而不是原样送进那个必定拒绝它的构造器。

只要样式的调用方（其余 20 处全是）行为完全不变。

**结果：这个函数从此不可能构造出一个会抛异常的格式化器。**

## 四、这次是怎么查出来的（因为前一版查错了方向）

0.3.32 的结论是"取正文失败，只是失败得很安静"。方向错了，原因是**开发环境里没有邮箱**，
所以当时只能推断，推断出来的那几条（密码没了、连不上、信被删了）**在你这台机器上一条都不成立**。

这次改成先取证：

1. 直接读本机的数据目录（设置 → 数据文件夹里写着在哪）——
   **5 个邮箱、189 封信、187 封正文完整躺在缓存里、今天全部同步成功、零错误**。
   → 取信没坏，问题在渲染。
2. 把**你自己的这 187 封真信**喂进真的界面代码里跑（数据全程没离开这台电脑）。
   第一次跑，屏幕上 **0 行**，控制台一行字：
   ```
   [ui] inbox failed to render: TypeError: Invalid option : option
       at new DateTimeFormat
       at dateTimeFormatter (src/i18n/index.ts:211)
       at formatDateTime (src/i18n/index.ts:228)
       at InboxView.tsx:787
   ```
   → 到这里原因就是确定的了，不是推断。
3. 修完再跑同一份真数据：**16 行列表出来了**，
   逐封打开，1440×900 和 390×844（安卓那个尺寸）两种下都验证过：

   | 缓存里的正文 | 画出来的字数 | 图片 |
   | --- | --- | --- |
   | 123,215 字符 | 802 字 | 16 张 |
   | 50,319 字符 | 2,458 字 | 39 张 |
   | 40,655 字符 | 3,056 字 | 34 张 |
   | 38,114 字符 | 3,341 字 | 46 张 |
   | 9 字符 | 3 字 | 0 张 |

   中文、英文、纯文本、带图 HTML 全部正常。

## 五、装上之后

打开收件箱应该直接就是你的邮件列表，中间带着「今天 / 昨天 / 星期几」的分隔条。

**如果还是那块"此界面无法显示"的灰面板**，请把灰面板上那行**英文原话**发给我——
它是引擎的原话，故意不翻译，因为不同的话对应完全不同的修法。这一版修掉的是
`Invalid option : option` 这一句。

> 全程没有任何邮件被删除或修改。这个 bug 只影响"画不画得出来"，
> 服务器上的信、本机缓存的信，一封都没动过。
