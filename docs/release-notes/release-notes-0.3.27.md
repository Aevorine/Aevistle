# Aevistle 0.3.27

一句话：**该有的功能装上去了，装的过程中又挖出两个"看起来好好的"的坏东西。**

0.3.26 修的是「关了之后收不到提醒」。这一版做的是剩下的那批：
快捷键、界面重复标题、公式渲染、操作指南、独立安全审计。
**其中两条不是新功能，是在做新功能的时候撞出来的旧 bug。**

---

## 一、开关打开了，主进程根本不知道 ← 这是个旧 bug

「退出之后也继续收信」这个开关，除了 0.3.26 修的计划任务设置问题，还有第二个毛病，
而且完全独立：

渲染层把这些设置推给主进程用的是一个 React 副作用，它的依赖列表里
**漏了 `keepReceivingWhenClosed`**。

后果非常具体：

| 你做的事 | 实际发生的 |
| --- | --- |
| 打开这个开关 | **什么也没发生。**主进程收不到，计划任务不会建 |
| 打开开关，然后重启应用 | 这时候才建上 —— 因为副作用在挂载时会跑一次 |

所以它看起来"能用"，只是要重启才生效；而没人会想到去重启，
更没人会把"我打开了开关"和"要重启一次"联系起来。

现在依赖列表里每一个被读的值都在里面了。找到它，是因为在旁边加快捷键设置时，
新设置需要走同一条推送路 —— 顺手看了一眼那个列表。

## 二、界面上重复的功能名删了

从导航栏点进「验证码」，页面左上角再写一遍「验证码」—— 你刚点的那个标签还亮着，
上面就是这四个字。九个页面里有六个是这样，每个白白占掉一条竖向空间。

现在全部不显示了。

**但没有用 `display: none`。** 标题还在文档里，只是被裁掉看不见，原因有两个：

1. **读屏软件需要它。** `display: none` 会把元素从无障碍树里一起删掉，
   那样一个用读屏的人进到这个页面，会发现它根本没有标题。
2. **门禁需要它。** `ui-consistency` 这道门禁会巡视十个页面、量 `.page-title` 的字号，
   `layout-probe` 会盯着它不许掉到 16px 以下。第一版真用了 `display: none`，
   跑全量检查时立刻红了：

   ```
   FAIL  page title size: only 0 element(s) matched `.page-title` across the whole tour,
         under the minimum of 3. Nothing was measured, so nothing was checked —
         this is not a pass.
   ```

   **"一个都没量到"不算通过** —— 这句话是那道门禁自己写的，也是它这次真正起作用的地方。
   改成裁剪之后，元素照样被排版、照样能量，两道门禁继续管着一个谁也看不见的标题。

Codes 页面的副标题（"检查中…"、"上次检查于…"）保留 —— 那是实时状态，不是重复的名字。
第一版把整个文字块一起藏了，会顺手带走这个还在工作的状态显示。

## 三、一个键把窗口叫出来，再按一次收回去

新增：**`Ctrl + Alt + A`**。

它是全局的，这一点是重点：窗口收进托盘之后，**应用内的快捷键按不到**，
因为屏幕上没有窗口来接收按键。而"窗口不在"正是最需要这个键的时候。

**可以改，也可以关。** 设置 → 系统 →「用快捷键显示或隐藏窗口」，
直接把想要的组合敲进去。旁边那行字会立刻说结果：

- 正常 → 显示"在任何地方按 Ctrl+Alt+A 都能把这个窗口叫出来，再按一次收回去"
- **组合被别的程序占了** → 直接说"已经被别的程序占用了，换一个试试"
- 敲错了格式 → "这不是 Windows 认的组合。至少要带一个修饰键"

这三种状态都不是从"你存的值"画出来的，而是**回头去问系统真正注册成了什么**。
`globalShortcut.register` 被拒绝时返回 `false`，不报错、不抛异常 ——
照着自己的设置画界面，就会得到一个显示着某个组合、按下去什么也不发生的开关。
这跟 0.3.26 那个"任务在但不会跑"是同一种谎，所以用了同一种办法。

输入框是**失焦时才提交**，不是每敲一个字就提交：`Ctrl+Alt+A` 打字过程中会经过
`C`、`Ct`、`Ctr`，每一个都会被判为非法组合，并且在判之前先把正在工作的那个注销掉。

托盘那边本来就是对的，一并写清楚：**左键单击显示窗口，再单击一下收回去且任务栏不留**；
**右键出菜单**（下一个任务时间 / 打开 / 写邮件 / 定时任务 / 发送记录 / 全部暂停 / 退出）。

## 四、邮件里的公式，现在是公式

`$E = mc^2$`、`\[ \int_0^\infty e^{-x}dx = 1 \]`、`\(\sum_{i=1}^n i\)` ——
以前这些原样显示成一堆反斜杠和美元号，现在排成真正的数学。

用 KaTeX，但**输出的是 MathML，不是 KaTeX 平时那套 HTML**。这个选择有具体理由：

KaTeX 默认输出一堆靠 `katex.min.css` 定位、靠 KaTeX 自带字体绘制的 span，
那套字体是 **1.2 MB 的 WOFF2**。而邮件正文跑在一个**什么都不加载**的惰性 iframe 里，
相对路径的字体在那儿根本没有基准地址可解析 —— 而且这 1.2 MB 是每个用户每次启动都要付的，
换来一个绝大多数邮件根本用不到的功能。

`output: 'mathml'` 只吐一个 `<math>` 元素。浏览器用机器上已有的字体自己排。
**零字体、零样式表、零请求。**

KaTeX 本身（约 280 KB）也是**用到才加载** —— 先做一次不花钱的字符串检测，
真有分隔符才动态 import。没有公式的邮件，打开速度一点没变。

### 钱不是公式

这是这个功能最容易变成灾难的地方：

> Lunch is $12, dinner is $20.

天真的 `$…$` 规则会把 `12, dinner is ` 当成一个公式渲染出来。
这种句子邮件里到处都是，而一个**从来没写过公式的人**会突然发现自己的邮件显示错了，
并且完全不知道为什么。

两条规则挡住它：

1. **美元号必须紧贴内容**（前后不能是空格）—— `$12, dinner is $` 结尾是空格，出局。
2. **数字开头的片段必须带 TeX 特征**（`\` `^` `_` `{` `}`）——
   所以 `$2^{10}$` 渲染，`$100$`、`$5-$7` 不渲染。
   字母开头的不受这条限制，因为 `$x$`、`$a_1$` 是变量写法，没有货币长这样。

`<pre>` 和 `<code>` 整块跳过 —— 有人在邮件里贴 shell 脚本，那里的 `$PATH` 就是 `$PATH`。

不想要可以关：设置 → 通知 →「把邮件里的公式排出来」。

### 安全：这段代码跑在消毒之后

这是它值得单独说的原因。这个转换发生在 `sanitizeHtml` **之后**，
往一份已经清理干净的文档里塞新标记 —— 这正是"好心补功能，顺手开了个 XSS"的经典形状。

所以新增门禁 `check:math`，29 条，**真的跑代码，不是 grep 源码**：

| 组 | 钉死什么 |
| --- | --- |
| 能用 | 四种分隔符都渲染；行间/行内分得清；**输出必须是 MathML**（换回 HTML 输出在那个 iframe 里什么都看不见，几个月后会被当成样式 bug） |
| 安全 | 只扫标签**之间**的文字（`href="…$x$…"` 里的美元号永远不是分隔符）；`trust: false` 让 `\href` `\url` `\includegraphics` `\htmlClass` `\htmlStyle` 全部失效；**七条敌意输入，逐条断言"输出里不得出现输入里没有的可执行属性"** |
| 不打扰 | 没公式的邮件逐字节原样返回；三种价格写法都不动；`<pre>`/`<code>` 原样 |

安全那一组的断言写法本身改过一次：第一版查的是"整个输出里有没有 `javascript:`"，
它红了 —— 因为 `\href` 被拒绝之后，KaTeX 会把**原文当文字画出来**，
那串字符确实出现在输出里，一个字母一个 `<mi>`。那是文字，文字是死的。
按整串查会因为一个完全正确的渲染而变红，而让它变绿的唯一办法是把它改弱。
真正要看的是**有没有多出一个能执行、能跳转的属性**，那只可能在标签里。

破坏跳过标签的逻辑，这道门禁立刻红。

## 五、操作指南

新增 [`docs/GUIDE.zh-CN.md`](../GUIDE.zh-CN.md)。写给第一次用的人，只说"按哪里、会怎样"。

- **电脑**：装好先做的三件事、全部快捷键（全局的和窗口内的分开列）、托盘左键右键分别是什么、
  两种"关掉"的区别、更新怎么走、出问题先看哪一行字
- **安卓**：安装、**四项权限**（前三行全绿也不代表能收到，第四行才是真的在看服务活着没有）、
  华为/小米/OPPO/vivo/三星各自的自启动路径、通知上的"标为已读"、手势表、更新
- **两台设备同步**：配对码在哪、扫不了码怎么办、解除配对为什么只清本机这一侧

写的时候核对过每一句在代码里是否成立 —— 有一条"自检 → 导出报告"写完之后发现**根本没有这个功能**，
已经改掉了。指南里不写不存在的按钮。

## 六、独立安全审计

新增 [`docs/security-audit-2026-08-20.md`](../security-audit-2026-08-20.md)。

| 项 | 结论 |
| --- | --- |
| 签名私钥有没有进过仓库 | **没有。**全历史扫过，命中的 11 个文件逐个看过，全是处理密钥的源码；仓库里只有公钥 |
| 依赖高危漏洞 | 0.3.26 修掉 CVE-2026-40345，现在为零；GitHub 的 Dependabot 告警已变 `fixed` |
| 桌面端隔离 | contextIsolation / sandbox / nodeIntegration=false 都到位；CSP 里 `connect-src 'self'`，**渲染层发不出任何外部请求** |
| 安卓导出面 | 三个 `exported="true"` 逐个核过，都是必须的（启动器、系统独占广播、桌面小组件），其余全部不导出 |
| GitHub 配置 | Secret scanning + 推送保护 + Dependabot 都开着；CI 最小权限且不持有任何 secret |

**找到一个真缺口**：`main` 分支**没有任何保护**。后果不是理论问题 ——
那 60 多道门禁在 CI 里跑，但不是合并的必要条件，**0.3.24 就是门禁红着发出去的**；
而且任何拿到写权限的令牌都能强推覆盖发布历史。

**没有替你打开**，因为打开会挡住直接 push 到 main，而那正是现在发版用的方式，
擅自改会让下一次发版卡住。审计报告里给了两条现成命令，一条只要求门禁必须绿，
一条只挡强推和删除，你挑。

审计报告最后有一节写的是**没验的部分**：没做动态渗透、没审 Electron/Gradle 插件自身的供应链、
没做二进制加固评估、所有实测只在一台 Windows 11 笔记本上完成。写出来而不是留白。

## 门禁

两道新的，都真的跑代码，也都验过"把它要测的东西弄坏，它会红"：

| 门禁 | 条数 | 钉死什么 |
| --- | --- | --- |
| `check:math` | 29 | 公式真的渲染成 MathML；标签属性里的 `$` 永远不是分隔符；七条敌意输入不得引入可执行属性；价格不是公式 |
| `check:toggle-shortcut` | 30 | 用一个假的 `globalShortcut` 跑真模块：被占用要报"被占用"、格式错的绝不送进 `register`（那个会抛异常）、重复应用必须幂等、事后被别人抢走要如实反映；外加 main.ts 的接线（无条件应用、启动时也应用、退出时释放） |

`check:toggle-shortcut` 这道自己也踩了一次坑值得记：第一版用 `esbuild --bundle` 把
假 electron 内联进去，结果**被测模块改的是内联副本，测试看的是另一个实例** ——
全绿的代码被测成六条失败。那种假失败最危险，因为让它变绿最省事的办法就是把检查删掉。
改成不打包、只转译，然后把 `from "electron"` 改指到同一个文件，两边才是同一份对象。
