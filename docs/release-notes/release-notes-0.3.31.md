# Aevistle 0.3.31

一句话：**手机上多了两个手势——**从左边缘往右滑退出**，**长按格子先看一眼里面有什么**；
平板上联系人和模板变成左右两栏；再加一道闸门，专门抓"按了没反应"的按钮。**

---

## 一、从左边缘往右滑，退出当前界面

### 之前的问题

手机上，定时任务、联系人、模板这些界面是整屏铺开的，**出去的唯一办法是点右上角那个 ✕**。
390px 宽的手机上，那个位置正好是拇指够不到的角。

系统返回键是能用的，但现在的手机大多用手势导航——**没有返回键**，而滑动这件事，
恰恰是这个应用唯一没有响应的地方。

### 现在

手指从**最左边那一条（约 24px）**按下去，往右拖过屏幕四分之一就松手，界面退回主页。
中途反悔就往回拖，它会自己弹回去。

三个细节，都是有意的：

- **只有边缘那一条算。** 再宽一点，你在列表里左右滑动就会误退出。
  这条 24px 也是安卓系统自己返回手势的量级。
- **阿拉伯语界面是反的**——从右边缘往左滑。在从右往左排版的语言里，"起始边"本来就在右边。
  这不是加了个 if，是 `resolveSwipe` 在两种排版下都把"往内拖"叫作同一个方向。
- **松手之后不留任何 transform。** 这句话看着像内部细节，但它是这个应用踩过的坑：
  一个动画结束在 `translateX(0)` 上，就足以让所有 `position: fixed` 的东西
  以这个元素为参照系——这正是当年手机弹窗盖不满屏幕的原因。
  所以这里手指一松，那条属性是**整个删掉**，不是设成 0。

**不加在哪儿**：读邮件那个全屏界面没有加。它本来就有自己的左右滑关闭（从任意位置都行），
而且 Esc 在它上面是两段式的。同一块屏幕上两个重叠的手势，
只会让"到底触发哪个"取决于手指落在哪里。

## 二、长按格子，先看一眼里面有什么

主页九宫格以前是八个只有名字的门。**"里面有没有值得进去的东西"** 这个问题，
只能靠真的进去一次、看一眼、再退回来——手机上大约四秒。

现在按住任意一格约半秒，底下升起一张卡片，最多三行：

| 长按 | 你会看到 |
| --- | --- |
| 定时任务 | 几个已就绪 · 今天要发几个 · 下一次什么时候 |
| 工作日历 | 标了几个日期 · 几个定时在用它 |
| 联系人 | 几位 · 几位设了投递时段 |
| 模板 | 几个 |
| 发送记录 | 今天发了几封 · 失败几次 |
| 可靠性中心 | 有没有问题、有几处 |
| 配对 | 几台设备 · 有没有同步冲突 |

**全是零的时候字会淡下去**——"里面是空的"本身也是个答案，而且是最省时间的那个。

### 这些数字是可信的

算它们的那段代码（`core/home/tilePreview.ts`）是一个**纯函数**：给它数据，它给你数字，
不碰界面、不碰网络、不碰时间以外的任何东西。所以可以直接拿测试去砸它，
`npm run check:tile-preview` 现在有 28 条断言，其中四条盯着四种"看起来对、其实错"的写法：

- **"今天"按日历天算，不是按 24 小时算。** 今晚 23:30 的那封是今天的，
  明早 00:30 的那封不是——而按 `now + 86400000` 算的版本，这两个每天都会算错。
  （把它换成 24 小时版本重跑，闸门当场点名两条，退出码 1。验过。）
- **暂停的定时不算"已就绪"。** `jobs.length` 是最顺手的那个数字，也是错的。
- **"下一次"是所有任务里最早的那一个**，不是第一个任务的下一次。
- **没写预览的格子不画卡片**，而不是画一张空卡片。

### 排格子的入口没有少

以前长按 = 直接进排列。现在长按 = 先看一眼，**卡片里有「编辑主页格子」按钮**。
「更多」→「编辑主页格子」那条路一直都在，没动。
长按「更多」那一格仍然直接进排列——它本身就是个菜单，没有"里面有什么"可看。

换的理由只有一个：**"里面有什么"一天要问很多次，"这格该放哪"大概一辈子问一次。**
手势应该落在常问的那个上。

## 三、平板：联系人和模板变成左右两栏

屏幕宽 **600–840px**（竖着的平板、横过来的手机、笔记本分屏一半）时，
收件箱和设置早就是左右两栏了。联系人和模板不是——在 800px 的平板上，
点一下「编辑」，会弹出一个盖住整张列表的窗，而那张列表明明看得清清楚楚。
连着改三位联系人 = 开关三次窗。

现在这两个界面也分栏：**左边列表，右边正在编辑的那一位**。点左边下一行，右边直接换过去。
实测 800px 宽时是 375px 列表 + 377px 编辑栏。

「取消 / 保存」固定在右栏底部，不跟着表单滚走——600px 高的平板横过来时，
投递时段编辑器本身就比那一栏还高。

顺带把这件事做成了一个组件（`DetailShell`），所以以后哪个列表界面想要分栏，
是改一行的事，不是再抄一遍表单。**表单只写一份**是重点——同一个表单写两份，
迟早有人只给其中一份加字段。

## 四、新闸门：每个按钮都得真的有功能

「每个按钮应该有其的功能，而不是装饰」——这句话以前没有任何自动检查在管。
一个什么都不做的按钮能通过这个仓库里现有的每一道闸门：它能编译、能渲染、
尺寸对、对比度对、`check:tap` 说它有 44px。它只在有人按下去、什么都没发生的时候才暴露。

`npm run check:screen-titles` 现在多做三件事。它开一个 390×844 的窗口，
走遍 5 个底部标签和 8 个主页格子，然后：

1. **每个按钮都读一遍它的处理函数**。React 会把每个节点的 props 挂在节点自己身上，
   所以这不是"看源码猜"，是问 DOM"按下去到底会调用什么"。
   没有 onClick、没有指针处理、又没有 disabled 的，就是装饰品，点名报出来。
   本次实测：**320 个控件，全部有名字、全部接了东西。**
2. **每个按钮都得能被念出来**。没有文字、没有 aria-label、没有 title 的图标按钮，
   读屏软件只会念"按钮"——对看不见屏幕的人来说那就是装饰品。
3. **顺手验了这一版的三个新东西**：长按真的出卡片、左边缘拖真的能退出、
   800px 下联系人和模板真的分成两栏并量出各自宽度。

它**不点任何按钮**，而且永远不会。这些按钮里有的会发邮件，有的会删联系人。
一道"把所有按钮都按一遍"的闸门，是一道不能在有真账号的机器上跑的闸门——
那就只能在假数据上跑，而假数据恰恰是真接线 bug 藏身的地方。

还有一条保险：**这轮如果检查到的控件少于 40 个，直接判失败**。
`check-ui-consistency` 当年吃过这个亏——选择器改了名，闸门一个元素都没量到，
然后开开心心报了绿。"什么都没量，所以什么都没查"不算通过。

三条新断言都当场验过会拦：把 `edgeBack` 摘掉，它说"从起始边拖动没有关闭全屏页"；
把联系人的分栏关掉，它说"800px 下 contacts 仍然是一栏"。放回去，全绿。

## 这一版没动什么

收发信、定时、通知规则、同步、加密——一行没动。
桌面版界面没动（桌面本来就是侧边栏九个标签，没有这些问题）。
你的设置、账号、定时任务、已收邮件，全部原样。

## 升级方式

- **电脑**：设置 → 关于 → 检查更新；或直接下新安装包覆盖。
- **安卓**：下 `Aevistle-0.3.31.apk` 覆盖安装，数据不动。

校验：`SHA256SUMS.txt` 连同 GPG 签名 `.asc` 一起发布，
公钥指纹 `57753E473F94B09DB3AA9A6AB865B328D5535D9B`。
