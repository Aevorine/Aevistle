# Aevistle 0.3.3

0.3.0 只重构了主页。这一版把手机上**剩下四个标签页**（撰写 / 验证码 / 收件箱 / 设置）
和**平板**做完。

还有一件必须说的事：**那条"收件箱至少要看得见 9 行"的红线，过去一直在量一个空屏。**
详见最后一节。

---

## 撰写

**收件人和主题现在两行都看得见。** 以前它们挤在同一条 48px 的摘要条里，各被截掉约三分之二
——实测显示的是「david.chen@example.co… 季度汇报（第…」。**你最容易发错的两个字段，
恰恰是按下发送前看不全的两个。** 而且折叠状态下完全看不出有没有设密送。

**收件人加了上限。** 以前没有任何上限：手机上一个收件人片高 54px（删除按钮要满足 48px
触摸下限），实测 3 人约 240px、**10 人约 660px**——比剩下的可视区还高，会把正文顶出屏幕。
现在超过 2 人折成「+N」，点一下展开。

**这两行是用删掉别的东西换来的，不是白拿的。** 正文上方那条 28px 的标签行去掉了
（里面只有一个折叠着的排版开关和一个字数统计），排版工具移到操作条，字数统计移到
正文框右下角——那里不占任何高度，而且正好在你打字的地方。

实测（360×800 首屏）：正文框 **85.6%**，硬底线 85%。宽屏 820px 下 **90.9%**，
比改之前的 87.4% 还高。代价说在明处：手机上从 87.2% 降到 85.6%，用 1.6 个百分点
换了「两个字段都看得全」。

**没有给这一屏加标题栏。** 代码里记着：加过一条只有标题的窄带，正文掉到 82.4%，
当时的"修法"是把 85% 的底线改成 80——用放弃要求代替满足要求，当天回滚。

### 「周五 18:00 发」从 8-9 步变成 2 步

以前要走：点 🕐 → 全屏接管 → 点「重复、重试、条件…」→ **又一个全屏弹窗盖在上面** →
里面 13-14 个可点元素只有 1 个是你要的 → 选日期还要滚两个长列表。

现在点操作条上的时间，直接弹出一排：一小时后 / 今晚 20:00 / 明早 09:00 /
**本周五 18:00** / 下周一 09:00 / 自定义…。点一下就定好，**不开任何弹窗**。
真要设「每周重复 + 重试 + 条件」时，「自定义…」后面那条完整的路一步没少。

顺带修掉两个：
- **弹窗套弹窗**——「重复、重试、条件…」原来不关掉它下面那层，现在关。
- **设了时间就没法立即发送**——主按钮原来变成「定时发送」后点它是*再开一个弹窗*，
  现在直接安排好；「立即发送」也仍然够得着（在时间那个弹出列表的第一项，
  因为 360px 的操作条实在放不下第五个按钮，硬塞会把时间按钮压到 20px、
  不到 44px 触摸下限的一半）。

### 一个已经上线的 bug

0.3.0 把排版工具条从正文标签行挪到了操作条，但它那条"折叠时隐藏"的规则还写着旧位置。
规则不再匹配，于是**七个格式按钮一直显示着，而且盖在警告条上、把点击全吃掉了**。
这一版修好了。

副作用要说明：`layout-probe.mjs` 里有一条"七个格式按钮都要看得见"的检查，
它不点开工具条就量——工具条正确隐藏后，量到的每个按钮都是 0×0，这条检查现在
**空过**了。它过去之所以有意义，恰恰是因为这个 bug。要让它重新有意义，
得先让它点开再量；这一版没动它。

## 验证码

**看到第一个码之前要越过的控件，从 5 层压到 2 层、318px 压到 56px。** 四个按钮
（立即检查 / 我在等验证码 / 全部标为已读 / 清空记录）原来全在页头，而手机上页头是
整行独占的。现在页头是标题 + 两个图标，其余进右上角菜单。

**码从 20px 升到二号 29.33px。** 它本来是 32px，为了"一屏能放下三张卡"两次调小到
20px——可这一屏平时只有 0 到 2 条。为了不存在的第三张卡，牺牲了唯一真正的主角。

**「点整张卡就能复制」这件事，现在说出来了。** 这个功能一直都有，但卡片右边还画着
一个小复制按钮，所有视觉线索都在说"要点那个"。现在卡上直接写着，小图标去掉。

「立即检查」改成下拉刷新，菜单里保留同名入口——代码里的规矩是"找不到的手势就是退步，
所以这里没有任何东西只有手势"。

**旧的验证码一条都不藏。** 第一版曾把十分钟前的收进「显示更早的 N 条」，
代码注释写着"那个链接就是验证码去送死的地方"。

## 收件箱

**第一行邮件之前的控件，从 5 层、318px 压到一条 48px 的标题带。** 列表区从 369px
涨到 629px。

- **发件人显示姓名。**「招商银行」，不再是「招商银行 &lt;no-reply@bank.example.com&gt;」被截断。
- **有附件的标记改成回形针。** 原来是一个「@」字符——看到「@」没人会想到附件。
- **已读的邮件不再整行变淡。** 原来整行透明度降到 62%，包括标题。已读不等于不重要。
- **账号标签只在你有两个以上账号时才出现。** 单账号时它每行都在说同一句废话。
- **批量与破坏性操作收进「编辑」模式。** 那个红色的「全部从邮箱删除」不再常驻在主列表上
  ——现在静止状态下**主列表上有 0 个危险按钮**。
- 「自动检查频率」搬回设置页。它是设置，不是列表内容，但你每次进收件箱都要看见它。

**关于三行还是两行：** 预览里推荐的是三行一封（头像 + 发件人 / 主题 / 正文预览）。
真做出来量了：行高 81.8px，**只能放 7 行，红线是 9 行**。所以退回两行
（发件人+时间 / 主题+预览），实测 61px，9 行。**没有去动那条红线。**

## 设置

**手机上原来只有 12 行，但实际有 16 个分区。** 每日摘要、节日问候、日历订阅、设备配对
被标成"窄屏隐藏"，在手机设置页里**根本不存在**，只能从主页绕，其中三个还在「更多」里。
打开设置去找"每日摘要"的人，会一无所获且没有任何指引。**这四个分区找回来了**，
主页的入口也保留，两条路都能到。

其余改动：

- **顶上一张身份卡**：账号是谁、地址、是否正常，一眼看完。
- **分成四组**：常用 / 邮件 / 数据与设备 / 关于。
- **每行右边直接写当前值**——「跟随系统 · 标准」「已是最新」「未配对」「每天 08:00」。
  这一条尤其重要，因为**低于 760px 的屏幕会隐藏所有说明文字**，右边这个值是唯一能
  告诉你现状的东西。
- 动作行（备份、搬家）和设置行在视觉上区分开。
- 两行句子改成名词：「保存加密配对文件」→「加密配对文件」。

**没有把这 2326 行拆成 16 个文件**——这些分区共享大量状态；而且有三个检查脚本是
按文件名直接读这个文件的源码的，代码搬走它们不会报错，只会**悄悄不再检查**。

## 平板

平板过去是**放大的手机**：768px 宽仍是单栏，多出来的宽度全变成空白。

现在 600–839px 之间，**收件箱和设置都是左右两栏**：左边列表，右边内容。
600 这个断点本来就在三个已声明的宽度里，没有新增。

实测 768×1024：收件箱 319px 列表 / 401px 阅读区；设置 280px 索引 / 440px 内容。
边界扫过一遍——599px 单栏、**600px 分栏**、839px 分栏、**840px 关掉**（桌面版不变），
每个宽度横向溢出都是 0。手机端（<600px）完全不变，仍然是全屏阅读器。

阅读器没有被复制一份：图片/正文的防错乱计数器、沙箱化的正文框、三条远程图片策略提示、
链接确认框，全部是同一套代码在两个位置渲染。

## 两个"从来没被测过"的毛病

做平板两栏时顺带撞出来的，都不在这一轮的范围里，如实记下来：

1. **手机版阅读器一直显示 5 个内联图标，而不是溢出菜单。** `14-growth.css` 里
   一条 `@media (max-width: 839.98px)` 先把 `.reader__actionsFull` 设成隐藏，
   30 行后又用同等优先级、**不带任何条件**地设回显示——后者在每个宽度都赢。
   这一版只在平板阅读区里修正了它，手机上仍是老样子。
2. **外观设置里有两个控件低于 44px 触摸下限**（分段控件 42px、配色色块 32px）。
   之所以一直没被发现，是因为**没有任何闸门会打开设置弹窗去量里面的东西**。
   平板两栏把外观直接渲染在页面上，闸门立刻就红了。已在平板范围内修正，
   **手机上（<600px）这两个控件仍然是 42px 和 32px。**

第 2 条和这一版发现的另外两件事是同一个模式：闸门测的东西和用户看到的东西不是一回事。

## 那条 9 行红线，一直在量一个空屏

`layout-probe.mjs` 里有一条会让构建失败的规则：360×800 下收件箱至少要看得见 9 行。
它是上一轮为了"界面统一"写的，本意是好的。

**但它只有在存在邮箱账号时才量真实的行；否则它拿一个"没有账号的空收件箱"的
685px 区域去除。** 而真有邮件时，那块区域只有 369px——**实际只放得下 5 行**。

也就是说这条红线过去一直在对着一个没人会看到的屏幕通过。现在它量的是真实行：
改完之后 **9 行**（一个账号）。

这和 0.3.0 里发现的"检查脚本连不上应用、只测一屏"是同一类问题：
**一个守卫如果没在守它以为在守的东西，比没有守卫更糟，因为它还让人放心。**
