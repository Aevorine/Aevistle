# Aevistle 0.3.32

一句话：**收件箱点开一封邮件，正文位置是一片空白——这一版把那片空白修掉了，
并且加了一道闸门，它现在会在每次发版前真的点开一封邮件确认它不是空的。**

---

## 一、你报的那件事：点开邮件，什么都没有

### 先说结论

**这是一个真 bug，而且是这个项目里最难被发现的那一类。** 它不报错、不崩溃、
不在任何日志里留痕，而且这个仓库里那 77 道闸门**没有一道能发现它**——
因为对每一道闸门来说，那个界面都是"正常"的：它渲染出来了、尺寸对、对比度对、
每个按钮都能点。

### 它到底是什么

阅读界面的正文区，代码里写的是这么一句：

```
正在加载 ? 骨架屏 : 有正文 ? 正文 : null
```

最后那个 `null` —— **既不是正在加载、也没有正文的时候，画一个"什么都没有"。**

而这第三种情况在**每一个平台上都到得了**：

| 到得了的原因 | 谁会碰上 |
| --- | --- |
| 保存的邮箱密码没了 | 换过密码 / 授权过期 |
| 邮箱服务器连不上或太慢 | 网络、公司网关、服务商抽风 |
| 这封信在上次同步之后被删了 | 在别的设备上删了 |
| **压根没有取正文的通道** | 浏览器里直接打开 `dist/` 的时候，100% 触发 |

碰上任何一种，屏幕上就是：主题、发件人、日期，然后**一大片白**。
有一条提示条弹出来说失败了，**四秒后它也消失了**，于是剩下的就是一片白，
没有原因、没有解释、也没有任何一个可以按的东西能改变它。

**一片空白和"这封邮件本来就是空的"长得一模一样。** 应用等于在替这封邮件说谎。

### 现在是什么样

正文区**永远不会是空的**。取不到正文时，那个位置现在是：

```
  ⚠

  这封邮件的内容没能取回来

  邮件还在服务器上，什么都没有被删掉。常见原因是保存的密码没了、
  邮箱服务器连不上，或者这封信在上次同步之后被删了。

  ┃ 上次同步时存下的摘要，不是完整正文
  ┃ （这里是这封信的摘要，本来就存在本机上）

  ┌──────────────────────────────────┐
  │ No IMAP password stored for this │   ← 引擎的原话，故意不翻译
  │ account                          │      这一行是拿去贴给别人看的
  └──────────────────────────────────┘

            [ 重试 ]
```

三件事，按有用的顺序：

1. **告诉你内容是"没取到"而不是"没有"**；
2. **把已经在本机上的那段摘要拿出来给你看**——它本来就存着，列表里那一行显示的就是它。
   服务器连不上的时候，至少还能看见这封信的第一句。标签写明了"这是摘要不是正文"，
   把摘要当正文显示等于夸大应用手里有多少东西；
3. **给一个真的能按的「重试」**。会跳过本地缓存重新取一次。

那一行英文报错**故意不翻译**——`No IMAP password stored for this account` 和
`connect ETIMEDOUT` 是两个完全不同的问题、两种完全不同的修法，翻译过的版本谁也帮不上。
这一行可以直接选中复制。

> **说清楚一件事**：这一版修的是"看不见原因"，不是"网络问题"本身。
> 你的电脑上到底是哪一种原因，我在这里看不到——但从这一版起，**应用会当场告诉你是哪一种**。
> 按一下「重试」，如果还是同一句话，把那行英文发我就行。

## 二、新闸门：`check:inbox-reader`

「收件箱能不能正常显示内容」以前没有任何自动检查在管，**一次都没有跑过**。

现在每次发版前，闸门会在 **1440×900 / 800×1200 / 390×844** 三个尺寸上各做一遍：

1. 往本地存一个 5 封信的假邮箱，启动应用；
2. 打开收件箱，**数出来必须正好是 5 行**，而且第一行必须同时有发件人和主题；
3. 点开第一封，然后**只看正文区、不看抬头**——抬头在这个 bug 的整个生命周期里
   一直是好的，那正是它这么难被发现的原因；
4. 正文区必须是三样东西之一：**邮件正文 / 加载骨架 / 失败面板**。是 `null` 就判失败；
5. 如果是失败面板，它必须**带一个真的接了函数的「重试」按钮**，
   必须**带上那段本地摘要**，而且文字不能少于 20 个字符。

**验过它真会拦**：把修复撤回成原来那个 `null`，三个尺寸同时报

> `the reader opened with an empty body — no message frame, no loading state and no failure panel. This is the blank-reader bug; the header alone rendered 64 characters.`

退出码 1。修复放回去，三个尺寸全过。

它**不需要真的邮箱账号**，假数据是直接写进 `aevistle.state.v1` 的——需要真账号的闸门
等于只能在一台机器上跑的闸门。而浏览器版本**本来就取不到正文**，
所以这个失败路径不是模拟出来的，**是真的**。

---

## 这一版没动什么

收发信、定时、通知规则、同步、加密、签名——一行没动。
收件箱的列表、搜索、筛选、手势也没动（列表本来就是好的，闸门现在会一直盯着它）。
你的设置、账号、定时任务、已收邮件，全部原样。

## 升级方式

- **电脑**：设置 → 关于 → 检查更新；或直接下新安装包覆盖。
- **安卓**：下 `Aevistle-0.3.32.apk` 覆盖安装，数据不动。

校验：`SHA256SUMS.txt` 连同 GPG 签名 `.asc` 一起发布，
公钥指纹 `57753E473F94B09DB3AA9A6AB865B328D5535D9B`。
