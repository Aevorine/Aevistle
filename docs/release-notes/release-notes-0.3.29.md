# Aevistle 0.3.29

一句话：**0.3.28 让"已读的邮件也提醒"变成可选的。这一版让"提醒谁"变成你说了算——
并且给了你一个按钮，一次就能分清"是设置的问题"还是"是通知根本没通"。**

---

## 一、先解决"我怎么知道到底哪儿坏了"

过去四个版本，"没收到提醒"这句话背后其实有五种完全不同的原因，而应用一种都说不出来。
你只能改一个开关、等一封邮件、再猜。

这一版在 **设置 → 通知** 顶上加了两样东西，都是一眼能看完的：

### 「发一条测试通知」按钮

按下去立刻弹一条，走的是**真实邮件用的同一条通道**。不收邮件，也不发邮件。

- **弹出来了** → 通知通道是通的。问题在"哪些邮件算值得提醒"，往下看第二节。
- **什么都没出现** → 是 Windows / 安卓的系统层挡住的，跟应用里任何设置都无关。

一次按钮，把五种原因先砍掉一半。这是这一版里最小的改动，也是最该早点有的。

### 「最近 24 小时」

按钮下面直接给数字：

```
到 12 封 · 提醒 3 封 · 拦下 9 封 · 共 47 次同步
  · 6 封已在别的设备上读过
  · 2 封超出了"算新到"的时间窗
  · 1 封发件人不在名单里
```

这些数字**本来每次同步就在算**，只是算完就扔了。现在留 24 小时，按"哪条规则拦的最多"
排序——因为有用的是那一句主要原因，不是一张六行的表。

**只记数字。** 没有发件人、没有主题、没有摘要、没有邮件 id。这份记录会进备份文件、
也会跟着设备同步走，一份会泄露它所诊断的信箱的诊断工具不值得留着。

## 二、"别乱响，但重要的别漏"

设置 → 通知 → **「什么样的邮件值得打断你」**。三条规则，从粗到细：

| 规则 | 效果 |
| --- | --- |
| **按账户** | 招聘垃圾那个账户永远不响，工作账户照常响。有两个以上收信账户时才出现 |
| **只提醒这些发件人** | 一行一个邮箱或域名。**只要名单里有东西，其他人一律不响** |
| **主题里出现这些词时一定提醒** | 一行一个词。这些词能穿过"已在别处读过"、"发件人不在名单里"、"免打扰时段"三道拦截 |

三个都留空 = 每封新邮件都提醒，和 0.3.28 完全一样。**升级不会改变你现在的行为。**

### 三个刻意的设计，每一个都有理由

**空名单是"没意见"，不是"谁都别响"。**
这是整个应用里唯一一处"空"和"非空"意思相反的设置，写反了就是：你还没配置完，
应用已经永远安静了——邮件照收、照列，一条提醒都没有。那正是这个功能要修的病。
门禁 `check:notify-policy` 把这一条放在第一个检查，`--selftest` 专门把它反过来，
确认门禁真的会红。

**关键词默认是空的，不是预置"验证码/发票/面试"。**
关键词能压过免打扰时段。一个出厂就带着"凌晨三点可以叫醒你"权限的词，不该是我们替你填的。
输入框下面给了 `+ 验证码` `+ 发票` `+ 面试` 三个一点就加的建议——同样的方便，但你点过。

**静音的账户，关键词也穿不过去。**
你把一个账户静音，是明说了"这里永远别来找我"。能被一个词绕过去的静音开关不叫静音开关。

### 手机关着应用的时候也算数

这三条规则在安卓后台用 Java 又实现了一遍（`AppSettingsSignal` + `InboxSyncRunner`），
因为后台同步的进程里根本没有 WebView，网页那一套一行都跑不了。
一条只在"应用开着"时生效的规则，就是一条假规则——而应用关着时收到的提醒，
恰恰是这些开关主要管的那些。

顺带修掉后台那边一个顺序错误：**免打扰的判断原来写在"看每一封邮件"之前**，
所以关键词在夜里永远无效——而深夜正是验证码到达的时候。现在先攒出这一批，
只有整批里没有任何"急件"时，免打扰才生效。门禁里有一条专门盯这个顺序，
防止哪次重构又把它挪回去。

## 三、某个账户悄悄坏掉，现在会主动说

**连续 3 次同步失败**（默认间隔下 = 15 分钟联系不上）会弹一条通知，说清是哪个账户。
之后 **6 小时**内不再重复；账户一恢复就清零，下次再坏是新问题，立刻报。

以前这种情况只在收件箱页面显示一行红字。那行红字对"正看着这个页面"的人刚好；
对真正会丢邮件的那种故障——三周前改了密码、每五分钟失败一次、而那个页面谁也没打开过——
它什么用都没有。

3 次不是随手定的：1 次是过隧道，2 次是邮件服务器重启，3 次连续失败已经越过所有临时原因了。

---

## 四、五个账户不再互相拖累

原来每次自动同步，**所有账户在同一个瞬间一起开始**。一两个账户时这没问题；
五个就是"点一次刷新要等最慢那个信箱"的原因——五次 TLS 握手、五次 IMAP 登录、
五次信箱扫描同时开始，在手机上、在移动网络下。

实测过的例子：一个账户连接要 36.7 秒（预算是 10 秒），另外四个健康账户全堵在它后面。

现在**最多三个同时**，并且**一个账户失败不再作废其余四个的结果**——
原来用的 `Promise.all` 只要有一个抛错就整批丢掉，包括那个已经把验证码取回来的账户。

三不是拍的：两个比三个慢，超过三个在手机能有的任何网络上都不再变快
（等服务器是主要开销，但每次同步的**开头**是一次 TLS 握手，那在低端机上不便宜）。

## 五、收件箱：这一天从哪儿开始

列表里每一天的第一封前面加一条分隔条——**今天 / 昨天 / 星期几**（一周内）/ **日期**（更早），
右边是那一天有几封。滚动时钉在顶上，因为"我现在看的是哪天"是滚动**中**的问题，
不是分隔条划过去时的问题。

日界线按**本地午夜**算，不是拿时间戳除以 86400000——后者是 UTC 午夜，
在北京是早上八点，会把一封 22:00 发的邮件划进"明天"。

虚拟滚动本来就是量真实行高的，所以分隔条比邮件行矮不会让滚动条乱跳。

## 六、门禁：两个新的，一个进了 CI

新增 `check:notify-policy`（62 项）和 `check:sync-limit`（39 项），都带 `--selftest`：
故意把规则改坏，要求门禁必须变红——**一个不会失败的门禁不是门禁**。

其中几条是安全项而不是功能项：

- 域名白名单 `example.com` **不能**匹配 `example.com.attacker.net`
  （那是今天就能注册的域名）。用的是右锚定 + 必须有一个点，不是 `endsWith` 子串。
- 邮箱白名单 `a@b.com` **不能**匹配 `evil-a@b.com`。
- 24 小时记录里**不能出现** `from` / `subject` / `snippet` / `id` 任何一个字段。

另外把**发版校验搬进了 CI**。`check:signing` 验的是"已经发出去的那个签名，
用已经发出去的那个公钥能不能验过"——也就是陌生人唯一能做的那件事。
它写好几个月了，一直只在维护者自己机器上手动跑，而且总是和它要检查的那次发布在同一次操作里，
那恰恰是最不可能发现"这步被跳过了"的时刻。现在 GitHub 上发布一次，它自己跑一次。

## 七、还有一处

收件箱左上角那个大写的「收件箱」标题去掉了（保留给读屏软件）。
你是点导航栏进来的，那一行是在复述你刚做过的事，而它占的正是"未读几封 / 上次几点检查"
那行状态应该在的位置。其余每个页面早就这么做了，这一个是漏网的。

## 升级

- **电脑**：设置 → 更新 → 检查更新，或直接下新的安装包覆盖装。
- **安卓**：下 APK 覆盖装，数据不会丢。

**不会改变你现在的行为**：三条新规则全部默认空/关，测试按钮和 24 小时统计只是多出来的东西。
