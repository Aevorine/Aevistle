# Aevistle 0.1.10

这一版只做一件事：把「验证码 / 登录链接」这块从**能用**做到**说得清、等得起、信得过**。

起因是一封微软的密码重置邮件——验证码是 `390089`，屏幕上显示的却是 `98052`，也就是微软总部 One Microsoft Way 的邮政编码。它不报错、不闪退、字也印得清清楚楚，就是错的。这是这个 App 最不该出现的一类失败。

---

## 为什么会是 98052

三件事凑在一起才会这样，缺一件都不会：

1. **中文关键词表里有「验证码」，没有「代码」**。而这封信写的是「密码重置**代码**」「你的**代码**如下」。于是整封邮件被判定为"一个关键词都没命中"，直接绕过了打分逻辑。
2. **无关键词时的兜底太软**——只要正文短、全文只剩一个数字串，就直接采信它。它不知道 `Redmond, WA` 后面跟着的五位数是邮编，不可能是验证码。
3. **`390089` 压根没参与竞争**。验证码在 HTML 里是被逐段包裹的样式块，剥掉标签之后变成 `3 9 0 0 8 9`，看上去不再是一串数字。真正的答案消失了，页脚的邮编就成了"唯一的那个数字"。

## 现在怎么修的

- **关键词表大幅扩容**：中文补上 代码 / 安全代码 / 一次性密码 / 动态密码 / 临时密码 / 登录码 / 口令 等，英文补上 security code / one-time passcode / confirmation code / PIN 等，法西俄阿同步扩。漏一个词的代价不是"分低一点"，是整封信掉进最不敢说话的那条路径。
- **先划掉不可能是验证码的数字，再打分**：美国州名后的邮编、中文「邮编/邮政编码」、门牌与楼栋号、客服热线与传真、金额、版权年份，都在参与竞争之前就被剔除——而且只划掉那几个数字，不划掉整行（HTML 转文本经常把整封信压成一行，划整行会把验证码一起吃掉）。
- **被拆开的验证码先拼回去**：`3 9 0 0 8 9` 会被识别并还原，零宽字符也先清掉。
- **无关键词的兜底改成全文最严的一条路**：正文要短、必须六位、全文不能有第二个候选，否则宁可什么都不说。少给一次验证码，代价是回邮件里看一眼；给错一次，代价是登录失败加上搞不懂为什么。
- **常见发件人挂专用规则**：微软、谷歌、苹果、GitHub、亚马逊、支付宝/淘宝、微信/QQ、PayPal 等，直接按它们固定的写法取值。

### 顺带修掉一个更早的 bug

新加的语料库第一次跑就抓到了它：数字串的边界规则把紧邻的句号也当成了"这串数字还没结束"，所以 **`Your code is 615204.` 这种句末的验证码，一直以来一个都提取不到**。现在只有当点号另一侧还是数字时才拒绝（`192.168.1.100`、`12.50` 仍然不会被误认），普通标点不再能让一个验证码凭空消失。

## 每张卡片现在能自证

点「为什么是它」，会看到：

- **选中它的理由**——命中了哪个关键词、离得多近、是不是六位、是否符合该发件人的已知写法；
- **这封邮件里的其他数字**，以及它们各自出局的原因（`98052 · 是邮政编码`）；
- 如果挑错了，**「这个才对」/「这些都不对」一键纠正**，纠正结果按发件人域名记住——记的不是"这次别选 98052"，而是"这家的验证码在『你的代码如下』后面"，所以下个月换了新验证码依然有效。

以前它挑错的时候，屏幕上没有任何东西可看、可点。现在有了。

## 链接不再是一串看不懂的地址

- **九类用途识别**：一键登录 / 验证邮箱 / 重置密码 / 激活账户 / 确认订阅 / 查看订单 / 账户管理 / 退订 / 统计跳转。卡片上写的是「点此登录 · 登录 live.com」，不是四十个字符的跟踪参数。
- **四项可核查的风险标注**，每一条都是一个事实而不是一个结论：跨站（落地域名和发件人对不上）、未加密（明文 http）、中转（跳转包装，显示的地址不是终点）、一次性（带令牌，点第二次通常就废了），另有相似域名（punycode）和纯 IP。
- **有效期倒计时**：从正文里读「15 分钟内有效」「expires in 10 minutes」等十余种中英法西俄阿写法，按邮件**发出时间**起算并实时倒数，过期的卡片置灰划掉——不是从你打开 App 那一刻算起，那样会凭空多给你十分钟。
- **二维码**：电脑上收到、手机上登录的场景，扫一下就过去了。

**全程不联网**。不预取、不解跳转、不发任何请求——这是别人主动寄给你的邮件，悄悄去访问里面的链接，等于把这个客户端变成对方的"已读回执"。

---

## 不用再等五分钟

- **「立即检查」**放在页面第一个位置，点一次就强制收信 + 重新提取，只高亮这次新增的。
- **「我在等验证码」**：接下来 60 秒每隔几秒看一次，收到就自动复制到剪贴板，到时自动停——不留任何后台轮询。自动复制只在这个窗口内发生，因为覆盖剪贴板是会丢东西的。
- **失败说人话，六种结果各说各的**：没有新邮件 / 有新邮件但里面没验证码 / 还没有账户开启收件 / 邮件服务器拒绝了登录 / 连不上服务器 / 其他（原样附上服务器的原话）。一句"检查失败"哪儿也去不了。

## 工程上的两道闸

- **`npm run check:code-extract`** —— 40 个用例，其中将近一半**期望什么都不返回**。误报直接让构建失败，漏报只报告不拦。只由正例组成的测试集，分不清"提升了命中率"和"顺手把邮编、电话、版权年也一起给了出来"。
- **`npm run check:qr`** —— 二维码是自己实现的（不给这个主打无服务、无遥测的 App 加运行时依赖），但不靠"看着像"来判断对错：12 组载荷逐个模块和参考实现对拍，含中文 UTF-8 和 89×89 的大码。二维码编码错了不会报错，只会画出一张很像二维码、但扫不出来的图。
