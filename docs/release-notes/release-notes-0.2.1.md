# Aevistle 0.2.1

Three things about *reaching* the app, finishing what 0.2.0 started on *looking*
at it.

---

## 文字大小 — Text size

**设置 → 外观 → 文字大小**，三档：标准 / 大 / 最大（16 / 18 / 20px）。

放大的不只是字，还有字周围的间距。这是有意的：只把字放大而间距不动，得到的是"一个挤在一起的小界面配了大字"，而不是一个大界面。这个应用的字号和间距本来就全部用相对单位写的，所以改一个根值，整套刻度按比例一起动。

用百分比而不是固定像素，是为了**不覆盖你手机自己的字体大小设置**——系统那一层仍然叠加生效。写死 20px 会悄悄取消掉安卓的无障碍设置，那正好和这个开关的目的相反。

实测最大档下，手机上可点控件仍然只有两种高度，没有任何一处低于 48px 的触摸下限。

## 单手模式 — One-handed reach

**设置 → 外观 → 单手模式**，默认关闭。

手机是在底部握住的，屏幕比拇指长。这个应用已经把能放下去的都放下去了（底部标签栏、发送按钮），但每个页面自己的标题行和它上面的按钮天生在顶部——在 6.7 寸的手机上，右上角是个需要两只手的距离。

打开后整屏内容下移 16vh。实测在 360×800 的手机上，卡片顶边从 y=101 降到 y=229，进入拇指弧线内。

**代价说在明处**：让出 128px 的内容高度。在写信页，这 128px 是从正文框里出的（485px → 357px）。所以它默认关闭，由你决定这笔交易划不划算。

底部标签栏不跟着动——一个把导航推出屏幕的单手模式，解决的是问题的另一头。

## 手机上终于能搜索了

命令面板（`Ctrl+K`）在手机上**只有一个入口**：主页上的一块磁贴。也就是说从「撰写」「验证码」「收件箱」「设置」这四个标签页——五个里的四个——**没有键盘就完全打不开它**。

不是坏了，是压根没有门。

现在页面标题栏会画一个搜索按钮，「验证码」「主页」「收件箱」「设置」都有了。设置页为此重新装回了标题栏，用的是 `hideTitle`——这个参数当初就是为这种"只要动作行、不要标题"的情况写的。

**写信页故意没有。** 那个页面在窄屏上是刻意不要顶栏的：代码里记着，之前试过加一条只有标题的窄带，结果正文框掉到 82.4%，撞破了这个页面 85% 的硬底线，而当时的"修法"是把底线从 85% 调到 80%——用放弃要求来代替满足要求。为了一个搜索按钮再来一次不值得，所以写信页的搜索仍然是"切一个标签页"的距离。

## 顺带修掉

`IconButton` 把 `className="icon-btn"` 写死在属性展开之前，任何调用方传入自己的 class 都会**静默替换掉它**，连带丢掉按钮的形状和 48px 触摸下限。现在是合并而不是替换。

## 门禁

`check-tap-targets.mjs` 加了第五个测试场景：手机竖屏 + 125% 字号。否则新加的文字大小功能一个守卫都没有。实测该场景下仍然只有两种控件高度，没有低于 44px 的元素。

59 项检查全部通过。
