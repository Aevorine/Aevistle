# Aevistle 0.3.8

**收件箱现在默认显示图片，而且打开邮件不联网。**

这两件事听起来矛盾，做法是把"下载图片"和"打开邮件"彻底拆开：

```
10:03  邮件到达  ->  后台取图 -> 安全扫描 -> 重新编码 -> 存到本机
14:27  你打开它  ->  只读本机缓存，一个请求都不发
```

---

## 先说清楚：这挡得住什么，挡不住什么

营销邮件里那张 1x1 的透明图，存在的唯一目的就是在你打开邮件的那一刻，从你的
网络地址向对方服务器发一次请求。这一次请求告诉发件人三件事：**这个邮箱是活的、
邮件是什么时候被读的、读它的 IP 是多少。**

预取之后：

| 发件人还能知道 | | |
| --- | --- | --- |
| 你什么时候打开的 | **不能** | 取图发生在邮件到达时，和你无关 |
| 你打开了几次 | **不能** | 第 2 次到第 41 次打开，请求数都是 0 |
| 你到底有没有打开 | **不能** | 收到就取，读不读都一样 |
| 你的 IP / 城市 | **仍然能** | ↓ 见下 |

**IP 这一条要老实说：挡不住。** Apple Mail 能挡住，是因为图片是从 **Apple 的服务器**
取的；本应用没有服务器，取图仍然是从你这台机器发出去的，只是换了个时间。

把时间换掉已经拿走了追踪最值钱的部分——"打开率"这个指标从此不再描述你。IP 那一条
需要一台中转服务器才能解决，代码里留了接口（`PROXY_RELAY_SETTING`），以后你想自己
架一台就能接上。**没有的东西不会假装有。**

## 图片在进你眼睛之前，被拆开重造了一遍

取回来的字节不会直接显示。流水线是：

**1. 看真身，不看标签。** 服务器说"这是 PNG"不算数，按文件头判断真实格式。两者对不上
就拒绝——服务器把 JPEG 写成 `image/jpg` 很常见，但"宽容"的代价是把一堆陌生字节喂给
一个你没打算调用的解码器，"严格"的代价只是少一张图外加一句说明。

**2. SVG 一律拒绝。** SVG 是 XML，能夹带 `<script>`，还能自己去联网加载别的东西——
正好是这套东西要关掉的那条通道。不管它自称什么格式，认出来就拒。

**3. 静态图整个重新编码。** 解码成像素、再重新生成一个文件。这不是"扫描一遍看看有没有
坏东西"——**扫描是一份别人想得到的清单，重新编码是反过来：活下来的，按定义就是那张图。**
所有不是图的部分自动消失：

- **EXIF —— 里面有 GPS 经纬度**、相机序列号、拍摄时间
- ICC 色彩配置、XMP、注释、内嵌缩略图
- **贴在图片结尾之后的任何数据**（在 GIF 结束符后面粘一个 ZIP 是标准的"多格式文件"
  手法，所有解码器都会忽略它——正因为如此，那里才是给**别的程序**藏东西的好地方）

解码用的是 Chromium 自己的解码器（桌面）和 Android 系统解码器（手机）。**解码器说
"我读不出来"是这里最有价值的信号**：畸形的、专门用来搞坏解码器的文件在这一步就没了。

**4. 动图保留动画。** 你选的这条。动图不做像素重编码（那会只剩第一帧），改成**按块
拆解重建**：逐块走一遍，只保留带像素和带时序的块，注释块、未知扩展块、结尾之后的
所有字节全部丢掉，循环次数那块保留（不然动图只播一次）。

**5. 追踪像素只统计不拦截。** 也是你选的。判定规则：1x1 到 4x4 的小图、整张全透明、
路径里有 `open`/`beacon`/`pixel` 这类词、URL 里带一长串只属于你的编号、查询串里带
你的邮箱地址。

规则是**按路径分段**匹配的，不是字符串包含——`包含("stat")` 会命中 `/static/logo.png`，
那是全网最常见的图片路径，这一条会让整个统计变成废话。

一条线索算怀疑，**两条对上才叫追踪**：CDN 路径里本来就可能有一长串哈希，营销链接里
本来就可能有 `open` 这个词。

## 被拦下的图片长什么样

一个灰色方块，加一行"为什么？"。点开告诉你是哪条规则拦的（格式对不上 / 是 SVG /
结尾藏了东西 / 解不出来 / 太大 / 根本不是图 / 指向你自己内网 / 没下载下来）。

**"被拦了"和"没下载下来"从头到尾是两件事**，一直分开走到界面上：没下载下来的给你
"重试"按钮，被拦下的不给——字节已经到了，拿同样的字节再扫一遍结果一样，代价是又给
发件人发一次请求。

顶部那条横幅只在真有话说的时候出现（图片全部来自本机 / 拦了几张 / 发现几个追踪器），
三样都没有就完全不显示。**每封邮件都挂一条隐私提示，两周之后就没人看了。**

## 顺带修好的：安卓的"重置全部"以前漏了图片缓存

以前安卓端的取图**根本没有缓存**，所以重置没什么可漏的。现在有了，所以补上了对应的
清除接口。清除的顺序是：**先停预取队列，再删文件夹，再恢复队列**——顺序错了会静默出错：
正在飞的那个预取任务会在删除**之后**把结果写回去，留下的恰好是你按下"忘记一切"那一刻
正在取的那几张。

## 两道新门禁，都验证过会真的失败

**`check:image-proxy`（88 项）** 比对桌面和安卓两套实现是否还一致：拦截理由词表、
追踪规则名、路径词表（逐字逐序）、各个阈值、六种语言的翻译是否齐全，以及**两端的
预取调用是否还在**——那一行没了，其它部分照样工作，只是隐私承诺变成假的，而且看不出来。

故意破坏验证：改词表 → 报"only in TS: newword"；改阈值 → 报两边数值；注释掉预取调用
→ 报"pictures would be fetched at open time again"；让 SVG 通过 → 报"no longer refuses SVG"。
四种都拦下了。

**`check:image-scan`（52 项）** 不比对一致性，直接造真文件跑：造一个带 GPS 坐标的 PNG、
一个带注释和尾部载荷的动图 GIF、一个伪装成 PNG 的 SVG，然后断言出来的东西里没有 GPS、
没有尾部载荷、注释没了、动画还在、SVG 被拒。**每个测试文件都是当场构造的**，所以能先
断言"输入里确实有 GPS"，再断言"输出里没有"。
