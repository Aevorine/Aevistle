# Aevistle

**Отложенные письма-напоминания, которые действительно доходят.**

Напишите письмо один раз — с файлами, изображениями или архивами во вложении —
и Aevistle отправит его вовремя, даже если окно закрыто. Один раз, каждый
будний день в 09:00, первого числа месяца или по любому выражению cron.
Он знает ваши государственные праздники, поэтому понедельничный отчёт не уйдёт
в понедельник, в который никто не работает. Windows и Android, без аккаунта,
без сервера, без телеметрии. Два устройства держат синхронизацию через вашу
собственную сеть — никакого облака посередине.

*Еженедельный отчёт по пятницам. Счёт первого числа. Поздравление в полночь,
пока вы спите.*

## Зачем это нужно

Отправить письмо умеет любой почтовый клиент. Почти никто не может пообещать,
что оно уйдёт в следующий вторник в 07:00 с нужным вложением — независимо от
того, вспомните вы об этом или нет и открыто ли приложение.

Aevistle прежде всего выполняет именно это обещание. Учётная запись не нужна —
он подключается к вашему SMTP-серверу (Gmail, Outlook, QQ, 163,
корпоративному) и отправляет. Приём тоже есть, но он не мешается, пока вы сами
его не включите: укажите для учётной записи IMAP-сервер, и Aevistle соберёт
единый почтовый ящик, автоматически выделит коды подтверждения и ссылки для
входа, а всё остальное по умолчанию оставит как есть.

**Его берут, чтобы** отправлять недельный отчёт каждую пятницу в 17:00 · напоминать классу о домашнем задании накануне · выставлять счёт первого числа каждого месяца · поздравить с днём рождения ровно в полночь, пока вы спите · напоминать об арендной плате каждые 30 дней · запланировать письмо так, чтобы оно пришло утром, а не в два часа ночи · получить код входа сразу по прибытии, не переключаясь между приложениями.

**Скорее всего, это не для вас, если** нужен полноценный почтовый клиент — без управления папками, без push-синхронизации IDLE, без удаления на сервере, и это намеренно, — маркетинговый инструмент с пикселями отслеживания и статистикой открытий или облачный сервис, который продолжает рассылку при выключенных устройствах. Aevistle отправляет и читает с *вашей* машины через *ваш* ящик — именно поэтому ему не нужна собственная учётная запись и он ничего не собирает.

## Приватность

У Aevistle нет сервера. Не нужно заводить учётную запись, нет телеметрии и нет
отчётов о сбоях.

Короткий фиксированный список того, что вообще покидает ваше устройство:
**SMTP-соединение с вашим собственным провайдером**; **IMAP-соединение с вашим
собственным провайдером**, только для учётных записей, где вы включили приём;
**внешнее изображение в полученном письме**, только когда вы попросили именно
его; **проверка обновлений** к `api.github.com`, если вы её не отключили; и
**таблица государственных праздников на один год**, когда вы нажимаете
«проверить онлайн». Последние два разрешены белым списком по хосту *и*
точному пути и уходят из доверенного процесса, а не из той части приложения,
которая отрисовывает почту — у неё исходящего доступа в сеть нет вовсе.

Сопряжение двух устройств не добавляет в этот список ничего. Они общаются друг
с другом внутри вашей собственной сети, без какого-либо облака и без
сервера-посредника.

> При отключённых обновлениях каждый оставшийся запрос из этого списка — тот,
> для которого вы сами нажали кнопку.

Где что хранится, что происходит при переносе папки данных, и какие две вещи
намеренно остаются на месте → **[PRIVACY.md](PRIVACY.md)**.

| 📆 **Сетка месяца — это и есть расписание** | Перетащите, чтобы перенести, щёлкните, чтобы открыть, цвет — по загруженности дня, плюс метки получателей, предпросмотр текста и значки доставки. [→](FEATURES.md#the-month-grid-is-the-schedule) |
| 📥 **Приём почты по желанию** | IMAP, единый для всех учётных записей, внешние изображения по умолчанию заблокированы, коды подтверждения выносятся на отдельный экран. [→](FEATURES.md#optional-inbox) |
| 🔤 **Переменные подстановки** | Поля контакта для каждого получателя плюс календарные вроде `{{nextWorkday}}`, вычисляемые в момент отправки, с Cc и Bcc, убранными из копий. [→](FEATURES.md#merge-variables) |

## Новое в 0.1.16

Исправления телефонной вёрстки, появившейся в 0.1.15 — ни одна возможность не
изменилась, и ничто в том, как почта планируется, отправляется, хранится и
шифруется, не затронуто.

- **Диалог — это экран, а не карточка, парящая над ним.** Раздел настроек
  открывался с полем по всему периметру, а снизу просвечивала панель вкладок.
  Содержательные диалоги теперь занимают весь экран и закрываются кнопкой в
  своём заголовке; короткие подтверждения намеренно остаются карточками.
- **Экраны, открытые с «Главной», теряли свою основную кнопку.** Скрытие
  дублирующегося заголовка скрывало и элемент, несущий главное действие экрана:
  в «Контактах» не оставалось способа добавить контакт. Теперь исчезает только
  текст заголовка.
- **Настройки перестали повторяться** — закреплённый подзаголовок, который
  пересказывал строки прямо под ним, и каждый раздел, называвший себя дважды.

Измерено на работающем окне, а не выведено из кода: три содержательных диалога
сообщают `(0, 0, 390, 800)` при окне `390×800`, подтверждение — `350×254` с
симметричными полями.

## Новое в 0.1.15

- **📲 Android обновляется сам.** Проверка обновлений работала всегда, но
  загрузка и установка были только на рабочем столе, поэтому телефон мог
  объявить о новой версии и предложить лишь ссылку на веб-страницу. Теперь он
  получает APK внутри приложения, с индикатором прогресса, сверяя его с
  опубликованным вместе с выпуском `SHA256SUMS`, и передаёт системному
  установщику — который по-прежнему просит подтверждение. Файл пишется в
  приватное хранилище приложения, а не в общую папку загрузок.
- **🏠 Вкладка «Главная» и нижняя панель, которая помещается.** Девять вкладок
  никогда не помещались на экране в 360 px; панель незаметно превратилась в
  горизонтальную прокрутку, четыре из них были за краем экрана. Теперь их пять
  — Написать, Коды, Главная, Входящие, Настройки — а расписания, контакты,
  шаблоны, рабочий календарь и журнал отправки живут за «Главной». Боковая
  панель на рабочем столе по-прежнему перечисляет все девять, и `Ctrl+1`–`Ctrl+9`
  по-прежнему достают до всех девяти на обеих платформах.
- **⚙️ Настройки — это список, а не четырнадцать экранов прокрутки.** Шестнадцать
  разделов в одну колонку означали, что до «Конфиденциальности» нужно
  прокрутить мимо всех остальных. На телефоне это теперь шестнадцать строк,
  открывающихся по одной; на рабочем столе сохраняется сетка в две колонки.
  Пояснительный текст под переключателями на телефоне убирается —
  предупреждения и ошибки никогда.
- **📡 Сопряжение набирает нужную сетевую карту.** Раньше публиковался первый
  адрес, который перечислила система, а на машине с VPN, гипервизором или
  средой контейнеров это регулярно оказывался виртуальный адаптер, недоступный
  ни одному телефону, — четыре секунды ожидания на другом устройстве и ни
  единой подсказки. Теперь адреса ранжируются, выбранный печатается рядом с
  QR-кодом, а машина с несколькими сетями получает список для выбора.

Также исправлено: переключатели, у которых ползунок не двигался на старых
сборках Android System WebView, и запись «запускать при входе», которую запуск
из исходников мог оставить указывающей на собственное окно-заглушку Electron.

## Новое в 0.1.14

- **🔗 Сопряжение двух устройств только через вашу локальную сеть — и ничего
  больше.** Отсканируйте QR-код на другом устройстве: ECDH P-256 + AES-GCM,
  одноразовый токен, истекающий через две минуты, и ни облака, ни
  сервера-ретранслятора ни в один момент. Вы сами выбираете, что
  синхронизировать — учётные записи, расписание, контакты, шаблоны, внешний
  вид, — и управляете сопряжёнными устройствами с одного экрана. Устройства,
  которые не видят друг друга, вместо этого обмениваются файлом,
  зашифрованным PIN-кодом.
- **📅 Календарь знает про почту.** Метки получателей и число писем на каждый
  день, тепловая карта плотности, предпросмотр текста без выхода из сетки,
  местное время получателя, показываемое *прямо во время* перетаскивания при
  переносе, подсказка, когда отправка попадает на праздник, массовые действия
  над целой повторяющейся серией, фильтрация по учётной записи или
  получателю, значки статуса доставки и локальный адрес подписки `.ics` для
  рабочего календаря.
- **🎨 Новый визуальный стиль: runecircuit («符文电路»).** Классическая
  китайская тушь встречается с киберпанковым неоном, есть настоящие дневная и
  ночная формы, регулятор интенсивности атмосферы и двухосевой выбор
  акцентного цвета. Седьмой стиль — и первый, в котором есть погода.
- **🌾 24 солнечных термина (节气), вычисляемые, а не взятые из таблицы.**
  Используется формула положения Солнца по Meeus, а не встроенная таблица —
  поэтому нет года, на котором покрытие обрывается. Термины только подсвечивают
  календарь и никогда не влияют на время отправки.

## Загрузка

Свежая сборка — в разделе **[Releases](https://github.com/Aevorine/Aevistle/releases/latest)**.

| Платформа | Файл | Примечания |
|---|---|---|
| Windows 10/11 (x64) | `Aevistle-<version>-win-x64-setup.exe` | Установщик, создаёт ярлыки в меню «Пуск» и на рабочем столе |
| Windows 10/11 (x64) | `Aevistle-<version>-win-x64-portable.exe` | Один файл, без установки, работает с флешки |
| Android 7.0+ | `Aevistle-<version>.apk` | Телефоны и планшеты. Сначала разрешите «установку неизвестных приложений» для браузера или файлового менеджера. |

`<version>` — это номер, указанный на странице
[последнего выпуска](https://github.com/Aevorine/Aevistle/releases/latest);
значок вверху страницы читает его оттуда же. Здесь он намеренно не записан,
чтобы эта таблица не могла устареть.

> **Проверка загрузки.** В каждом релизе публикуются `SHA256SUMS.txt`,
> отделённая подпись `SHA256SUMS.txt.asc` и открытый ключ, которым она сделана:
>
> ```bash
> gpg --import aevistle-public-key.asc
> gpg --verify SHA256SUMS.txt.asc SHA256SUMS.txt
> sha256sum -c SHA256SUMS.txt
> ```
>
> Контрольные суммы подтверждают, что файл дошёл без повреждений; подпись
> подтверждает, что он выпущен ключом этого проекта. Отпечаток — в
> [SECURITY.md](../SECURITY.md).

> Windows SmartScreen предупредит о неизвестном издателе. Так выглядит сборка
> без платного сертификата подписи кода: выберите **Подробнее → Выполнить в
> любом случае** или сначала сверьте SHA-256 со страницей релиза.

## Быстрый старт

1. **Добавьте почтовый ящик.** Настройки → Добавить учётную запись. Выберите
   провайдера — сервер, порт и шифрование заполнятся сами.
2. **Получите пароль приложения.** Gmail, Outlook, Yahoo, iCloud, QQ и 163 не
   принимают обычный пароль от сторонних программ. В диалоге есть прямая ссылка
   на страницу создания.
3. **Проверьте подключение.** Одна кнопка. Авторизация без отправки письма —
   узнаете о проблеме сейчас, а не в 03:00.
4. **Напишите напоминание**, приложите нужное и нажмите **Запланировать**.

## Безопасность

Модель угроз, принятые меры и порядок сообщения об уязвимости —
в **[SECURITY.md](../SECURITY.md)**.

Кратко: у отрисовщика нет доступа к Node, включены изоляция контекста и строгая
CSP; любая строка, предназначенная для почтового заголовка, отвергается при
наличии перевода строки (именно так появляются открытые релеи); TLS-сертификаты
проверяются, если вы явно не отключили это для конкретной учётной записи;
HTML полученного письма очищается в основном процессе по строгому белому
списку ещё до того, как попадёт в отрисовщик, и показывается в изолированном
iframe без какого-либо выполнения скриптов при любых обстоятельствах; а
приёмник будильников в Android не экспортирован, поэтому никакое другое
приложение не заставит Aevistle отправить письмо.

Всё это можно проверить самостоятельно: `npm run audit:self` —
**21 проверка**, понятный вывод, код возврата 1, если что-то требует внимания.

## Сборка из исходников

**Требуется** — Node.js 20+, а для Android: JDK 17+ и Android SDK
(platform 36, build-tools 35+). `npm run build:android` находит установленные
JDK и SDK, даже если их нет в `PATH`, так что `JAVA_HOME` необязателен.

```bash
git clone https://github.com/Aevorine/Aevistle.git
cd Aevistle
npm install
```

| Задача | Команда |
|---|---|
| Запуск в браузере (без SMTP, всё остальное настоящее) | `npm run dev` |
| Проверка типов | `npm run typecheck` |
| Аудит безопасности (21 проверка) | `npm run audit:self` |
| Всё, что гоняет CI (42 проверки) | `npm run check` |
| Запуск настольного приложения | `npm start` |
| Сборка установщиков Windows | `npm run dist:win` |
| Сборка APK для Android | `npm run build:android` |

Подпись релиза для Android читается из `~/.aevistle/keystore.properties` или из
переменных `AEVISTLE_KEYSTORE*`. Если нет ни того, ни другого, сборка вернётся
к отладочному ключу — APK всё равно можно установить.

## Как всё устроено

Один интерфейс на React + TypeScript, две нативные оболочки.

```
src/core/        независимо от платформы: модель данных, движок повторов,
                 проверки, пресеты SMTP — без DOM, без Node, без Android
src/             интерфейс на React (шесть языков, семь визуальных стилей,
                 у каждого — настоящая светлая и настоящая тёмная форма)
    ↓ PlatformBridge — единственный шов между UI и операционной системой
electron/        Windows: nodemailer + imapflow, секреты через DPAPI, область
                 уведомлений, гибридный планировщик (тиковый и точный),
                 очистка HTML для полученной почты
android/         Android: JavaMail (отправка и приём), Keystore, AlarmManager + WorkManager
```

Движок повторов намеренно существует только в TypeScript. Он заранее вычисляет
список абсолютных меток времени, а планировщик каждой платформы лишь отвечает
«разбуди меня в момент T» — поэтому все календарные правила (високосные годы,
короткие месяцы, переход на летнее время, пропуск выходных) написаны один раз,
на одном языке, и проверяются без эмулятора.

Подробности — в **[ARCHITECTURE.md](ARCHITECTURE.md)**.

## Планы

Не обещания — то, что вероятнее всего появится дальше.

- [ ] OAuth 2.0 для Gmail и Microsoft 365, чтобы пароли приложений стали не нужны

предложения функций действительно приветствуются.

## Участие в разработке

Pull request'ы приветствуются. См. **[CONTRIBUTING.md](../CONTRIBUTING.md)**
для структуры кода и того, как выглядит хороший вклад, и
**[CODE_OF_CONDUCT.md](../CODE_OF_CONDUCT.md)** для того, как здесь принято
относиться друг к другу.
Добавить седьмой язык — это один файл и никаких сборочных инструментов:
система типов сама покажет, каких строк не хватает.

У сообщений об ошибках и запросов возможностей есть
[шаблоны](https://github.com/Aevorine/Aevistle/issues/new/choose); каждый pull
request прогоняет тот же `npm run check`, что и вы локально.
