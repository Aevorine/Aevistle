# Aevistle

**Отложенные письма-напоминания, которые действительно доходят.**

Напишите письмо один раз — с файлами, изображениями или архивами во вложении —
и Aevistle отправит его вовремя, даже если окно закрыто. Один раз, каждый
будний день в 09:00, первого числа месяца или по любому выражению cron.
Он знает ваши государственные праздники, поэтому понедельничный отчёт не уйдёт
в понедельник, в который никто не работает.
Windows и Android, без аккаунта, без сервера, без телеметрии.

*Еженедельный отчёт по пятницам. Счёт первого числа. Поздравление в полночь,
пока вы спите.*

## Зачем это нужно

Отправить письмо умеет любой почтовый клиент. Почти никто не может пообещать,
что оно уйдёт в следующий вторник в 07:00 с нужным вложением — независимо от
того, вспомните вы об этом или нет и открыто ли приложение.

Aevistle прежде всего выполняет именно это обещание. Учётная запись не нужна —
он подключается к вашему SMTP-серверу (Gmail, Outlook, QQ, 163,
корпоративному) и отправляет. Приём тоже есть, но он не мешается, пока вы сами
его не включите: укажите для учётной записи IMAP-сервер, и Aevistle соберёт
единый почтовый ящик, автоматически выделит коды подтверждения и ссылки для
входа, а всё остальное по умолчанию оставит как есть.

**Его берут, чтобы** отправлять недельный отчёт каждую пятницу в 17:00 · напоминать классу о домашнем задании накануне · выставлять счёт первого числа каждого месяца · поздравить с днём рождения ровно в полночь, пока вы спите · напоминать об арендной плате каждые 30 дней · запланировать письмо так, чтобы оно пришло утром, а не в два часа ночи · получить код входа сразу по прибытии, не переключаясь между приложениями.

**Скорее всего, это не для вас, если** нужен полноценный почтовый клиент — без управления папками, без push-синхронизации IDLE, без удаления на сервере, и это намеренно, — маркетинговый инструмент с пикселями отслеживания и статистикой открытий или облачный сервис, который продолжает рассылку при выключенных устройствах. Aevistle отправляет и читает с *вашей* машины через *ваш* ящик — именно поэтому ему не нужна собственная учётная запись и он ничего не собирает.

## Что он умеет

| | |
|---|---|
| 📮 **Отправить сейчас или позже** | Две главные кнопки закреплены внизу экрана составления при любом размере окна. Прокручивать ради отправки не приходится. Время отправки стоит рядом с ними — уже заполненное следующим целым часом, а не оставленное пустым, — и меняет вид вместе с правилом: дата и время для разовой отправки, время суток для ежедневной, еженедельной, ежемесячной или ежегодной — это и есть то поле, по которому такие правила на самом деле срабатывают, — и никакого редактора для выражения cron, потому что выражение *и есть* правило. |
| 📥 **Приём почты по желанию** | Включите IMAP для учётной записи — Aevistle сам подставит сервер, проверит его до сохранения и соберёт единый почтовый ящик из всех учётных записей: общим списком или с фильтром по одной, с выбранным вами интервалом проверки. Открытое письмо занимает всё окно; `Esc` возвращает назад. `J`/`K` переключают письма, `Ctrl+F` ищет внутри. Полученные вложения просматриваются на месте — изображения, PDF и текст — либо открываются системной программой, сохраняются куда угодно или показываются в файловом менеджере. Внешние изображения по-прежнему блокируются, а каждая ссылка открывается через подтверждение с настоящим адресом. |
| 🔑 **Коды подтверждения — на отдельном экране** | Коды и ссылки для входа автоматически извлекаются из приходящей почты и собираются на собственном экране: отправитель, тема, время получения и сам код — крупно, чтобы прочитать с одного взгляда. Нажатие в любом месте карточки копирует его. Уведомление приносит код с собой, так что открывать ничего не нужно, а история переживает удаление исходного письма. |
| 📨 **Письмо, которое превращается в напоминание** | Встречи, приёмы и сроки вычитываются из полученной почты на всех шести языках приложения, и одна кнопка превращает найденное в запланированное напоминание. Карточка показывает предложение, из которого взята дата, — чтобы её можно было проверить, а не поверить ей на слово, — и прямо сообщает, когда формулировка допускала больше одного прочтения. Настоящее приглашение несёт часть `text/calendar`, где дата уже указана точно; на Windows читается именно она, а не проза. Входящие на Android такие части не сохраняют, поэтому там остаётся разбор текста. Предпочтительный вид отказа — промолчать: пропущенная дата стоит одного перечитывания письма, а неверная — встречи. |
| ⚡ **Пакетная отправка** | Одно запланированное срабатывание может отправить одно и то же сообщение несколько раз подряд с интервалом в миллисекундах, который вы задаёте, — чтобы нагрузочно тестировать собственный канал отправки, а не рассылать спам. |
| 📎 **Любые вложения и картинки в теле письма** | Документы, изображения, архивы — всё, что укладывается в лимит провайдера. Вставьте скопированное изображение прямо в текст письма — оно появится встроенным; любое вложенное изображение также можно превратить из вложения в картинку внутри письма и обратно. Aevistle показывает реальный размер при отправке: base64 превращает файл на 20 МБ в 27 МБ — именно поэтому вложения «в пределах лимита» отбиваются. |
| 🖼️ **Картинки, которые действительно видно** | Каждое изображение письма — встроенное в текст, приложенное файлом или пришедшее во входящие — показывается миниатюрой, а не именем файла, по которому приходится гадать. Щелчок открывает полноэкранный просмотр: колесо — масштаб, перетаскивание — сдвиг, двойной щелчок переключает «вписать» и «100 %», поворот на четверть в обе стороны, отражение по горизонтали и вертикали, стрелки — переход к остальным изображениям письма, а рядом видны размер в пикселях, объём файла и формат — перед сохранением на диск или копированием в буфер. `Esc` закрывает картинку и только её. |
| 📆 **Сетка месяца — это и есть расписание** | В клетке каждого дня перечислено то, что в этот день действительно уходит: время, получатель, тема. Щелчок открывает это напоминание, перетаскивание на другой день переносит его, двойной щелчок по пустому дню начинает новое напоминание на эту дату. Перетаскивание говорит, что оно собирается сделать, прежде чем сделать это: разовая отправка переносится, а повторяющееся правило *меняется* — списка исключений по отдельным срабатываниям, куда можно было бы записать «этот вторник пропустить, отправить в четверг», здесь нет, и перетаскивание, молча переписавшее недельное правило, было бы хуже того, которое отказывается. Клетки закрашены по загруженности дня по постоянной шкале — 1, 2, 3, 5, 8 отправок, — поэтому тот же вторник в следующем месяце будет того же оттенка. Шкала, нормированная на самый занятый день на экране, перекрашивала бы весь месяц при каждом добавленном напоминании: это украшение, а не информация. |
| ⚠️ **Отправки, которые сталкиваются, и одна кнопка для этого** | Напоминания, попадающие в одну и ту же минуту, отмечены на том дне, куда они попали. Один щелчок разводит их в пределах ±5 минут, а затем называет те, что остались на месте, и почему: выражение cron владеет своей минутой, а сдвиг, который перешагнул бы полночь, — это смена *дня*, а несколько минут значить это не вправе. Меняется время суток у самого правила, то есть за ним последуют и все будущие отправки; об этом сказано в подтверждении, а `Ctrl+Z` возвращает всю пачку разом. |
| 🎌 **Рабочие дни, которые задаёте вы** | Государственные праздники, выходные по вашему усмотрению и рабочие субботы — на сетке месяца, где день переключается щелчком. Готовые отправные наборы для шести стран в один щелчок, расшифрованные китайские официальные таблицы вместе с переносами 调休 и импорт-экспорт `.ics`. Каждое напоминание само решает, следовать ли календарю, а сетка отмечает, какие отправки календарь *перенёс*, — единственное, что отвечает на вопрос «дала ли вся эта настройка хоть что-нибудь». Поиск официальных дат года по кнопке «проверить онлайн» не работал ни в одной сборке: собственная политика безопасности содержимого приложения отклоняла запрос из интерфейса, а сбой выглядел ровно как проблема с сетью. Теперь запрос уходит через доверенный процесс, а политика осталась такой же строгой, как была. |
| 🌐 **Рабочий день получателя** | У контакта может быть указан часовой пояс и рабочие часы, и адресованное ему напоминание попадает внутрь *его* дня, а не вашего: «каждый понедельник в 09:00», написанное в Шанхае, иначе придёт в Лос-Анджелес в 03:00 — в тот единственный час недели, когда почту не читает никто. Это правило применяется после рабочего календаря и после тихих часов и старше их обоих, поэтому письмо, выпущенное в утро получателя, вполне может уйти посреди вашей ночи; так функция работает, а не ломается. Учитывается только строка `To:` — тот, кого держат в курсе, не является адресатом, а копии нечего задерживать почту настоящего получателя. **Ничего никогда не откладывается и не теряется**: набор окон, который нельзя удовлетворить целиком, или просто неверно настроенное окно — об этом сообщается, а письмо уходит в заданное вами время. Редактор проговаривает последствие целой фразой — когда на самом деле уйдёт напоминание, поставленное на такой-то час, и который час будет в этот момент у получателя, — потому что любое значение в этой форме выглядит правдоподобно и ни одно из них нельзя проверить, просто перечитав. |
| 🗒️ **Сводка по собственному расписанию** | По желанию: одно письмо в день самому себе — что уходит сегодня, что предстоит в ближайшие семь дней и что с чем сталкивается. Это не фоновая задача, спрятанная где-то внутри: это обычное напоминание в вашем расписании, видимое на том же экране, его можно поставить на паузу и удалить, как любое другое, — другой версии этой функции приложение себе не позволяет. Там, где число является нижней границей, а не итогом, об этом сказано, а в теле письма стоит момент, когда оно было составлено: машина вполне могла отправить его на несколько часов позже. |
| 🎉 **Поздравления с праздниками — запланированные, а не отправленные** | Выберите страну и год — Aevistle рассчитает, на какие числа выпадают официальные праздники, и покажет список. Ничего не появляется, пока вы не нажмёте кнопку, а появляются после неё обычные видимые запланированные задачи. Идущие подряд дни с одним названием — это один повод: национальный праздник с 1 по 7 октября даёт одно поздравление, а не семь одинаковых писем за неделю. Для китайского года, который Госсовет ещё не объявил, берутся фиксированные даты и указывается, какой источник использован, — вместо того чтобы экстраполировать прошлогодний лунный календарь и ошибиться намеренно. |
| ⌨️ **Клавиатура и панель, которая не врёт** | У каждой вкладки есть номер, каждое сочетание перечислено, а сам перечень порождается из списка вкладок — поэтому он больше не разойдётся с действительностью так, как разошёлся только что. |
| 📤 **Напоминания можно забрать с собой** | Экспортируйте расписания в файл и импортируйте их в другой установке. Ни учётной записи, ни сервера, ни пароля в этот файл не попадает — его безопасно держать в резервной копии. |
| 📅 **Экспорт тех моментов, когда отправка действительно произойдёт** | Экспорт напоминаний в `.ics` может записать правило повторения — или те моменты, о которых приложение уже приняло решение, с учётом переносов по праздникам и тихих часов. Эти два варианта расходятся намеренно: «каждый будний день в 09:00» — верное правило и неверное расписание, как только календарь перенёс отправку с 1 октября на 8-е, и подписчик, читающий правило, видел бы план, которому Aevistle следовать не собирается. **Ограничение, сказанное вслух:** подписаться на сохранённый файл умеют Outlook, Thunderbird и Apple Calendar. Google Calendar — нет: он читает только публичные веб-адреса, а сервера, на который такой адрес можно положить, у приложения нет. Просчитанный список к тому же устаревает, как только выходит за пределы уже вычисленных моментов, — поэтому это режим, а не поведение по умолчанию. |
| ✒️ **Оформление без визуального редактора** | Полужирный, курсив, код, ссылки, списки и цитаты вставляются как Markdown в то же самое поле обычного текста. На выходе это превращается в безопасный для почты HTML, так что получателю достаётся оформление, а не звёздочки. |
| 🔤 **Переменные подстановки, в том числе календарные** | `{{name}}`, `{{email}}` и ваши собственные поля контакта подставляются отдельно для каждого получателя, а Cc и Bcc из копий убираются: рассылка — это сорок личных писем, а не одна переписка на сорок человек. Рядом с ними `{{nextWorkday}}`, `{{prevWorkday}}`, `{{holiday}}`, `{{nextHoliday}}`, `{{nextDayOff}}`, `{{daysToNextHoliday}}`, `{{workdaysLeftThisWeek}}` и `{{workdaysLeftThisMonth}}` читают тот же рабочий календарь, который решает, *когда* уйдёт письмо, и вычисляются в момент отправки — поэтому напоминание, перенесённое календарём на понедельник, не будет по-прежнему писать «до завтра». Переменной `{{isWorkday}}` намеренно нет: её пришлось бы выводить словом, на языке, которого эта часть приложения не знает. Переменную, которую нечем заполнить, оставляют на месте, а не стирают молча. |
| 🔍 **Поиск там, где нужно** | Ограничьте поиск по ящику отправителем, темой или текстом предпросмотра — потому что поиск по человеку вытаскивает каждую рассылку, где упомянуто его имя. |
| 👆 **Смахивание на телефоне** | Смахните письмо, чтобы убрать его или переключить признак прочтения. Удаления на сервере за этим жестом намеренно нет: оно необратимо, и ему нечего делать за движением пальца. |
| 📊 **Видно, что письмо ушло** | В каждой строке — последняя отправка, успешна ли она и сколько раз задача срабатывала. Разовые напоминания уходят на вкладку «Завершённые», а не остаются в списке, делая вид, что ещё ждут. |
| 🗑️ **Удаление, которое что-то значит** | Два разных действия, потому что это два разных запроса: убрать из Aevistle (возвращается из корзины, хранится семь дней) или удалить из почтового ящика на сервере (необратимо, и об этом сказано). |
| ✍️ **Режим фокуса** | `F9` убирает всё, кроме письма, и отдаёт ему всё окно. `Esc` возвращает остальное. На подписи — счётчик символов и байтов: один иероглиф это три байта, а лимит провайдера считает именно байты. |
| 🔁 **Настоящая периодичность** | Один раз · каждые N минут · ежедневно · еженедельно по выбранным дням · ежемесячно (с разумным правилом для 31-го) · ежегодно · полный cron из 5 полей. |
| 🔒 **Снимки вложений** | Запланируйте напоминание на следующий месяц — Aevistle хранит собственную копию файлов, так что перемещение или переименование оригиналов ничего молча не сломает. |
| ⏰ **Срабатывает при закрытом окне** | В Windows остаётся процесс в области уведомлений; в Android — точный будильник плюс WorkManager. Закрытие окна не отменяет напоминания. |
| 🌙 **Политика догона** | Ноутбук спал и пропустил три момента отправки? Выберите одну догоняющую отправку или пропуск. Три одинаковых письма утром вам не придут. |
| 🎲 **Разброс и выходные** | Разнесите отправки внутри окна, чтобы провайдер не принял всплеск за спам, и перенесите выходные срабатывания на понедельник. |
| 🔐 **Пароли остаются на месте** | Шифруются системой: DPAPI в Windows, аппаратное хранилище ключей в Android. Никогда не попадают ни в файл настроек, ни в экспорт. |
| 📂 **Ваша папка — ваши правила** | При первом запуске Aevistle спрашивает, где хранить данные, а **Настройки → Папка данных** позволяют изменить это позже. Он перенесёт то, что уже есть, **и исправит пути внутри существующих расписаний** — напоминание, созданное месяц назад, всё так же найдёт своё вложение. |
| 🔌 **Соединения, которые срабатывают** | Порт и шифрование не совпали? Aevistle попробует другое сочетание, которое принимает ваш провайдер, вместо отказа с «Unexpected socket close», а затем предложит сохранить то, что сработало. У каждой попытки есть предел времени, поэтому кнопка проверки всегда возвращает ответ. |
| 🩺 **Говорит, что произошло** | Успешная проверка показывает выбранную точку подключения и время отклика; неудачная называет причину и что изменить. На экране журнала есть доля успешных отправок и медианное время. |
| 🌙 **Тихие часы** | Ночные напоминания ждут утра. Ручная отправка никогда не задерживается — вы же за компьютером. |
| ⬆️ **Обновления внутри приложения** | Запрашивает GitHub Releases, скачивает установщик, сверяет его с опубликованным SHA-256 и передаёт системе. На Android APK открывается системным установщиком. Можно отключить; кроме самого запроса ничего не отправляется. На Android эта проверка не работала ни в одной выпущенной сборке: та же политика безопасности содержимого, которая не даёт телу письма открыть сокет, отклоняла и запрос обновления, а ошибка была неотличима от «нет сети». Теперь запрос уходит через доверенный процесс, по белому списку, привязанному и к хосту, *и* к пути, — а не за счёт послабления самой политики. |
| 🌍 **Шесть языков** | English, 简体中文, Français, Español, Русский, العربية — с полноценной раскладкой справа налево для арабского. |
| 🎨 **Шесть визуальных стилей, а не шесть оттенков** | Aurora, Graphite, Paper, Midnight, Nordic и «Высокая контрастность» — выбираются по плиткам предпросмотра в **Настройки → Внешний вид**. Стиль — это не подмена цвета: каждый заодно перенастраивает радиус скругления, межстрочный интервал и то, сколько тени вообще допустимо, — именно поэтому Graphite читается как другая программа, а не как та же самая в сером. У каждого стиля есть настоящая светлая форма и настоящая тёмная, так что «как в системе» продолжает работать при любом выборе. **Высокая контрастность** — тот случай, где дизайном является число: каждая пара «текст — фон» проходит 7:1, WCAG AAA, включая третичные отметки времени и семантические цвета на их собственных подложках, — а именно там AAA-схемы обычно тихо останавливаются. Границы в ней видны намеренно: 3,9:1 в светлой теме и 6,3:1 в тёмной, выше тех 3:1, которые требуются от границы элемента управления. Поверх стилей: светлая и тёмная темы по системе или зафиксированные, семь акцентных цветов — каждый стиль их перенастраивает, а не отнимает, поэтому выбор переживает переход на «Высокую контрастность», — две плотности и подбор шрифта по письменности: Songti (宋体) для китайского, Times New Roman для латиницы и пунктуации. |

## Загрузка

Свежая сборка — в разделе **[Releases](https://github.com/Aevorine/Aevistle/releases/latest)**.

| Платформа | Файл | Примечания |
|---|---|---|
| Windows 10/11 (x64) | `Aevistle-<version>-win-x64-setup.exe` | Установщик, создаёт ярлыки в меню «Пуск» и на рабочем столе |
| Windows 10/11 (x64) | `Aevistle-<version>-win-x64-portable.exe` | Один файл, без установки, работает с флешки |
| Android 7.0+ | `Aevistle-<version>.apk` | Телефоны и планшеты. Сначала разрешите «установку неизвестных приложений» для браузера или файлового менеджера. |

`<version>` — это номер, указанный на странице
[последнего выпуска](https://github.com/Aevorine/Aevistle/releases/latest);
значок вверху страницы читает его оттуда же. Здесь он намеренно не записан,
чтобы эта таблица не могла устареть.

> **Проверка загрузки.** В каждом релизе публикуются `SHA256SUMS.txt`,
> отделённая подпись `SHA256SUMS.txt.asc` и открытый ключ, которым она сделана:
>
> ```bash
> gpg --import aevistle-public-key.asc
> gpg --verify SHA256SUMS.txt.asc SHA256SUMS.txt
> sha256sum -c SHA256SUMS.txt
> ```
>
> Контрольные суммы подтверждают, что файл дошёл без повреждений; подпись
> подтверждает, что он выпущен ключом этого проекта. Отпечаток — в
> [SECURITY.md](../SECURITY.md).

> Windows SmartScreen предупредит о неизвестном издателе. Так выглядит сборка
> без платного сертификата подписи кода: выберите **Подробнее → Выполнить в
> любом случае** или сначала сверьте SHA-256 со страницей релиза.

## Приватность

У Aevistle нет сервера. Не нужно заводить учётную запись, нет телеметрии и нет
отчётов о сбоях.

Короткий фиксированный список того, что вообще покидает ваше устройство, и
больше ничего:

1. **SMTP-соединение с вашим почтовым провайдером** — ваше сообщение, до
   почтового ящика, который вы настроили.
2. **IMAP-соединение с вашим почтовым провайдером** — только для учётных
   записей, где вы включили приём, и только чтобы забрать почту этой записи.
3. **Внешнее изображение внутри полученного письма, только когда вы явно
   просите его загрузить** — по умолчанию каждое изображение заблокировано и
   заменено заглушкой, потому что удалённый `<img>` — старейший приём слежки
   в электронной почте. Сама загрузка защищена от перенаправления на вашу
   собственную сеть (никаких внутренних IP, никакого следования редиректам).
4. **Проверка обновлений**, если вы её не отключили: неаутентифицированный
   `GET` к `api.github.com` с вопросом о последней версии. Не несёт ни данных
   учётной записи, ни содержимого писем, ни статистики использования.
   Отключите её в **Настройки → Обновления**, и приложение никогда не сделает
   именно этот запрос по собственному почину.
5. **Таблица государственных праздников, только когда вы нажимаете «проверить
   онлайн»** — неаутентифицированный `GET` за датами одного года. И она, и
   проверка обновлений разрешены белым списком по хосту *и* точному пути, и обе
   уходят из доверенного процесса, а не из той части приложения, которая
   отрисовывает почту: у неё исходящего доступа в сеть нет вовсе.

При отключённых обновлениях каждый оставшийся запрос из этого списка — тот, для
которого вы нажали кнопку.

Всё хранится на вашем устройстве:

| | Windows | Android |
|---|---|---|
| Настройки, расписания, контакты, журнал | `<папка данных>\state.json` | хранилище приложения |
| Пароли почты | `secrets.json`, шифрование DPAPI | Android Keystore (аппаратный, где доступен) |
| Пароли IMAP | Тот же файл, то же шифрование, отдельная запись в хранилище ключей от SMTP-пароля этой учётной записи | То же хранилище ключей, отдельная запись |
| Снимки вложений | `<папка данных>\attachments\` | `<папка данных>/attachments` |
| Кеш полученной почты (тела писем, вложения) | `<папка данных>\inbox\` — ограниченный по возрасту и размеру кеш, лимиты настраиваются в **Настройках**; удалять безопасно — просто пересинхронизируется | `<папка данных>/inbox` |

Папка данных изначально находится в `%APPDATA%\Aevistle` на Windows и в частном
хранилище на Android; **Настройки → Папка данных** переносит её куда угодно,
куда вы можете писать. На Android выбор идёт между томами, в которые система
действительно разрешает приложению писать (частный, общий, SD-карта): папку,
выбранную через системный выбор документов, фоновая отправка спустя часы уже не
откроет.

Две вещи намеренно остаются на месте: пароли — они зашифрованы под вашу учётную
запись ОС и бесполезны в другом месте, и (на Android) расписание будильников —
чтобы извлечённая карта не помешала напоминанию сработать.

Экспорт настроек никогда не содержит пароль.

## Безопасность

Модель угроз, принятые меры и порядок сообщения об уязвимости —
в **[SECURITY.md](../SECURITY.md)**.

Кратко: у отрисовщика нет доступа к Node, включены изоляция контекста и строгая
CSP; любая строка, предназначенная для почтового заголовка, отвергается при
наличии перевода строки (именно так появляются открытые релеи); TLS-сертификаты
проверяются, если вы явно не отключили это для конкретной учётной записи;
HTML полученного письма очищается в основном процессе по строгому белому
списку ещё до того, как попадёт в отрисовщик, и показывается в изолированном
iframe без какого-либо выполнения скриптов при любых обстоятельствах; а
приёмник будильников в Android не экспортирован, поэтому никакое другое
приложение не заставит Aevistle отправить письмо.

Всё это можно проверить самостоятельно:

```bash
npm run audit:self
```

21 проверка, понятный вывод, код возврата 1, если что-то требует внимания.

## Сборка из исходников

**Требуется** — Node.js 20+, а для Android: JDK 17+ и Android SDK
(platform 36, build-tools 35+). `npm run build:android` находит установленные
JDK и SDK, даже если их нет в `PATH`, так что `JAVA_HOME` необязателен.

```bash
git clone https://github.com/Aevorine/Aevistle.git
cd Aevistle
npm install
```

| Задача | Команда |
|---|---|
| Запуск в браузере (без SMTP, всё остальное настоящее) | `npm run dev` |
| Проверка типов | `npm run typecheck` |
| Аудит безопасности | `npm run audit:self` |
| Запуск настольного приложения | `npm start` |
| Сборка установщиков Windows | `npm run dist:win` |
| Сборка APK для Android | `npm run build:android` |

Подпись релиза для Android читается из `~/.aevistle/keystore.properties` или из
переменных `AEVISTLE_KEYSTORE*`. Если нет ни того, ни другого, сборка вернётся
к отладочному ключу — APK всё равно можно установить.

## Как всё устроено

Один интерфейс на React + TypeScript, две нативные оболочки.

```
src/core/        независимо от платформы: модель данных, движок повторов,
                 проверки, пресеты SMTP — без DOM, без Node, без Android
src/             интерфейс на React (шесть языков, две темы)
    ↓ PlatformBridge — единственный шов между UI и операционной системой
electron/        Windows: nodemailer + imapflow, секреты через DPAPI, область
                 уведомлений, очистка HTML для полученной почты
android/         Android: JavaMail (отправка и приём), Keystore, AlarmManager + WorkManager
```

Движок повторов намеренно существует только в TypeScript. Он заранее вычисляет
список абсолютных меток времени, а планировщик каждой платформы лишь отвечает
«разбуди меня в момент T» — поэтому все календарные правила (високосные годы,
короткие месяцы, переход на летнее время, пропуск выходных) написаны один раз,
на одном языке, и проверяются без эмулятора.

Подробности — в **[ARCHITECTURE.md](ARCHITECTURE.md)**.
