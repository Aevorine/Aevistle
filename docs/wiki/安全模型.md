## 邮箱授权码应怎样保管

QQ、163、126 的客户端授权码用于第三方客户端登录邮箱，应按密码保管。只在邮箱官方页面生成授权码，并在 Aevistle 的账户配置中输入。不要把授权码贴到 GitHub Issues、聊天截图或公开教程里。

如果怀疑授权码已泄露，先到邮箱服务商的官方账户设置中停用或撤销对应授权码，再生成新的授权码，并更新 Aevistle 中的账户配置。

## 本地保存不等于邮件不经过服务商

Aevistle 在设备上保存设置、计划和联系人；发送邮件时，仍会把邮件交给你配置的 SMTP 服务商。启用收信后，应用还会连接对应的 IMAP 服务。因此，QQ、网易或单位邮箱的服务器仍参与邮件处理，接收方的服务器也会接收邮件。不要把“本地调度”理解成邮件内容从不离开设备。

通过应用主动检查更新或获取新的中国节假日数据时，会访问相应的网络来源。节假日功能优先使用已包含的数据，手动获取数据时会显示来源；本地已有数据和网络更新需要区分。

## 工作邮件、共享电脑与备份

- 在单位电脑上使用单位邮箱时，遵守单位自己的邮箱权限和设备管理要求。涉及合同、人员名单或内部资料时，先确认附件和收件人。
- 在公共或共享电脑上，不要把便携版连同账户数据交给其他人使用。保管好系统账户，并在离开时锁屏。
- 备份或导出的计划、联系人和活动日志仍可能包含真实邮箱、邮件主题、正文或文件路径。即使文件里没有密码，也不能直接公开上传。
- 更新应用前保留必要的个人备份；排查问题时，不要把完整数据目录作为公开附件。

## 下载文件怎样核对

从[项目 Releases](https://github.com/Aevorine/Aevistle/releases)下载应用，比较文件的 SHA-256 与该版本清单，再按 [SECURITY.md](https://github.com/Aevorine/Aevistle/blob/main/SECURITY.md)验证签名。校验值用于发现文件变化；签名用于验证发布清单是否来自项目的签名密钥。Windows EXE 的 Authenticode 证书签名与清单签名是不同的校验方式。

项目签名私钥保存在仓库之外，不会作为发布附件或 Actions 机密配置上传。本地控制接口默认关闭；开启后仅通过本机回环地址访问，并使用会话令牌鉴权。通过控制接口立即发送邮件，还需要单独开启发送权限。

## 用中文反馈时应删除哪些内容

可以提供应用版本、Windows 或 Android 系统版本、手机品牌、邮箱类型，以及不含隐私的复现步骤。公开截图和日志中，请遮盖：

- 邮箱授权码、账户密码和授权令牌；
- 真实收件人、通讯录、邮件正文和附件内容；
- 含本人姓名的电脑用户名、完整本地路径，以及单位内部服务器信息；
- 本地控制接口配置和任何可用于访问接口的令牌。

普通使用问题可通过 [Issues](https://github.com/Aevorine/Aevistle/issues/new/choose)反馈。涉及漏洞、越权或数据泄露时，使用[私密漏洞报告](https://github.com/Aevorine/Aevistle/security/advisories/new)，不要先发公开 Issue。
